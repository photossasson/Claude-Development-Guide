הכנת סביבת העבודה

בפרק הזה נתקין את Claude Code על כל מערכת הפעלה נפוצה, נתחבר לחשבון, נלמד לעדכן ולהסיר את ההתקנה, ונטפל מראש בתקלות ההתקנה השכיחות. בסוף הפרק תהיה לכם סביבה עובדת ומאומתת, מוכנה ל-Session הראשון בפרק 3.

מה בדיוק אנחנו מתקינים

לפני שמריצים פקודות, שווה להבין מה ההתקנה בעצם נותנת. Claude Code הוא תוכנית שורת פקודה (CLI) אחת בשם claude: קובץ בינארי עצמאי שרץ בטרמינל שלכם, מדבר עם המודלים של Anthropic דרך הרשת, ומפעיל כלים מקומיים (קריאת קבצים, עריכה, הרצת פקודות) על המחשב שלכם. כל שאר הממשקים שנפגוש בפרק הזה, תוסף ה-VS Code, תוסף ה-JetBrains, אפליקציית ה-Desktop וה-Web, הם עטיפות שונות לאותה יכולת ליבה. לכן ההשקעה בהתקנת CLI תקינה משתלמת בכל מקרה: היא הבסיס שכולם נשענים עליו.

אחרי התקנת Native טיפוסית, אלו הקבצים והתיקיות שנוצרים אצלכם (ב-Windows הנתיבים המקבילים תחת %USERPROFILE%):

מבנה קבצים אחרי התקנה (macOS / Linux / WSL)
~/.local/bin/claude          # המשגר (Launcher) שנמצא ב-PATH
~/.local/share/claude/       # הגרסאות המותקנות עצמן
~/.claude/                   # הגדרות, היסטוריית Sessions, נתוני עזר
~/.claude.json               # קובץ מצב והגדרות גלובלי

ההפרדה הזאת חשובה: הסרת ההתקנה מוחקת את שתי התיקיות הראשונות, אבל ההגדרות וההיסטוריה שלכם (שתי האחרונות) נשמרות אלא אם תמחקו אותן במפורש.

הערה חשובה: לא צריך Node.js

בעבר Claude Code הותקן כחבילת npm וחייב התקנת Node.js. היום ההתקנה המומלצת היא Native Installer שמוריד קובץ בינארי עצמאי, ללא תלות ב-Node.js. רק אם תבחרו להתקין דרך npm תצטרכו Node.js בגרסה 22 ומעלה (ראו בהמשך). כלי החיפוש ripgrep מגיע בדרך כלל כלול בהתקנה.

בנוסף תצטרכו חשבון מתאים: מנוי בתשלום ל-Claude (תוכנית Pro, Max, Team או Enterprise) או חשבון Claude Console עם חיוב לפי שימוש. התוכנית החינמית של Claude אינה כוללת גישה ל-Claude Code. נרחיב על כך בסעיף ההזדהות.

שיטות ההתקנה: מבט על

קיימות כמה דרכים רשמיות להתקין את Claude Code. כולן מתקינות את אותו קובץ בינארי, וההבדל הוא בניהול העדכונים:

פקודות ההתקנה הרשמיות מורידות סקריפט ומריצות אותו ישירות (curl ... | bash או irm ... | iex). זו הדרך המתועדת של Anthropic, וההורדה נעשית ב-HTTPS מדומיין רשמי. מי שמדיניות הארגון שלו אוסרת על התבנית הזאת יכול להשתמש במנהלי החבילות החתומים (Homebrew, WinGet, apt, dnf, apk) או לאמת ידנית את חתימת ה-GPG של קובצי השחרור, תהליך שמתועד במלואו בעמוד ה-Setup הרשמי תחת "Binary integrity and code signing".

התקנה על Windows (התקנה מקומית)

על Windows יש שתי אפשרויות: התקנה מקומית (Native Windows) או התקנה בתוך WSL2. ההבדל המרכזי: התקנה מקומית מתאימה לפרויקטים וכלים של Windows, אבל אינה תומכת ב-Sandboxing (הרצת פקודות בבידוד). WSL2 מתאים למי שעובד עם כלי Linux ותומך ב-Sandboxing. אין צורך בהרשאות Administrator להתקנה.

שלב אחר שלב: PowerShell

  1. פתחו PowerShell (חפשו "PowerShell" בתפריט התחל). ודאו שהשורה מתחילה ב-PS C:\. אם אין PS בתחילת השורה, אתם ב-CMD ולא ב-PowerShell.
  2. הריצו את פקודת ההתקנה הרשמית:
PowerShell
irm https://claude.ai/install.ps1 | iex
  1. אם אתם מעדיפים לעבוד ב-CMD, השתמשו בפקודה הייעודית ל-CMD במקום:
CMD
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
  1. סגרו ופתחו מחדש את הטרמינל, ואז ודאו שההתקנה הצליחה עם claude --version.
אזהרה: אל תערבבו בין ה-Shells

הפקודה עם irm עובדת רק ב-PowerShell, והפקודה עם && עובדת רק ב-CMD. אם קיבלתם The token '&&' is not a valid statement separator אתם ב-PowerShell והרצתם את פקודת ה-CMD. אם קיבלתם 'irm' is not recognized אתם ב-CMD והרצתם את פקודת ה-PowerShell.

מומלץ (אך לא חובה) להתקין גם Git for Windows. כשהוא מותקן, Claude Code משתמש ב-Git Bash להרצת פקודות (כלי ה-Bash). בלעדיו, Claude Code מריץ פקודות דרך כלי PowerShell במקום. אם Git מותקן במיקום לא סטנדרטי, אפשר להגדיר את הנתיב בקובץ settings.json:

.claude/settings.json
{
  "env": {
    "CLAUDE_CODE_GIT_BASH_PATH": "C:\\Program Files\\Git\\bin\\bash.exe"
  }
}

חלופה להתקנה ב-WinGet (ללא עדכון אוטומטי; עדכנו ידנית עם winget upgrade Anthropic.ClaudeCode):

PowerShell
winget install Anthropic.ClaudeCode

התקנה על WSL2

WSL2 (סביבת Linux בתוך Windows) הוא הבחירה הנכונה אם הפרויקטים שלכם משתמשים בכלי Linux, או אם אתם רוצים Sandboxing להרצת פקודות. שלבי ההתקנה:

  1. אם WSL2 עדיין לא מותקן, פתחו PowerShell כ-Administrator והריצו wsl --install (מתקין Ubuntu כברירת מחדל), ואז הפעילו מחדש את המחשב.
  2. פתחו את הטרמינל של הפצת ה-WSL שלכם (למשל Ubuntu). חשוב: מתקינים ומריצים את claude בתוך טרמינל ה-WSL, לא ב-PowerShell.
  3. הריצו את פקודת ההתקנה של Linux:
Bash (בתוך WSL)
curl -fsSL https://claude.ai/install.sh | bash
  1. סגרו ופתחו מחדש את הטרמינל והריצו claude --version לאימות.
Best Practice

שמרו את הפרויקטים שלכם בתוך מערכת הקבצים של WSL (למשל ~/projects) ולא תחת /mnt/c/. עבודה על קבצים שיושבים בצד ה-Windows איטית משמעותית וגורמת לבעיות הרשאות.

אם אתם על WSL1, הרצת claude עלולה להיכשל עם Exec format error. הפתרון הנקי: שדרוג ל-WSL2 עם wsl --set-version <DistroName> 2 מתוך PowerShell.

התקנה על macOS

על macOS (בגרסה 13.0 ומעלה, מעבדי Intel ו-Apple Silicon כאחד) הדרך המומלצת היא ה-Native Installer:

  1. פתחו את Terminal (דרך Spotlight: חפשו "Terminal").
  2. הריצו:
Bash / Zsh
curl -fsSL https://claude.ai/install.sh | bash
  1. ההתקנה ממקמת את Claude Code תחת ~/.local/share/claude ויוצרת קיצור ב-~/.local/bin/claude. סגרו ופתחו מחדש את הטרמינל והריצו claude --version.

חלופה למשתמשי Homebrew:

Bash / Zsh
brew install --cask claude-code

קיימים שני Casks: claude-code עוקב אחרי ערוץ stable (בדרך כלל שבוע מאחורי הגרסה האחרונה, מדלג על גרסאות עם רגרסיות משמעותיות), ו-claude-code@latest מקבל כל גרסה מיד. התקנות Homebrew אינן מתעדכנות אוטומטית: הריצו brew upgrade claude-code מדי פעם.

התקנה על Linux

על Ubuntu, Debian ורוב ההפצות, ה-Native Installer הוא הדרך הפשוטה ביותר:

Bash
curl -fsSL https://claude.ai/install.sh | bash

לשרתים מנוהלים, Anthropic מפרסמת מאגרי חבילות חתומים ל-apt, dnf ו-apk. כך מגדירים את ערוץ ה-stable ב-Debian/Ubuntu:

Bash (apt)
sudo install -d -m 0755 /etc/apt/keyrings
sudo curl -fsSL https://downloads.claude.ai/keys/claude-code.asc \
  -o /etc/apt/keyrings/claude-code.asc
echo "deb [signed-by=/etc/apt/keyrings/claude-code.asc] https://downloads.claude.ai/claude-code/apt/stable stable main" \
  | sudo tee /etc/apt/sources.list.d/claude-code.list
sudo apt update
sudo apt install claude-code

העדכון בהמשך נעשה עם sudo apt update && sudo apt upgrade claude-code. הוראות מקבילות ל-dnf (Fedora/RHEL) ול-apk (Alpine) נמצאות בתיעוד הרשמי בעמוד ה-Setup. על Alpine נדרשות חבילות נוספות (bash, curl, libgcc, libstdc++, ripgrep) והגדרת USE_BUILTIN_RIPGREP=0.

התקנה דרך npm (לסביבות שדורשות זאת)

החבילה @anthropic-ai/claude-code מתקינה את אותו קובץ בינארי, אך דורשת Node.js בגרסה 22 ומעלה (החל מגרסה 2.1.198 של Claude Code):

Bash
npm install -g @anthropic-ai/claude-code
סכנה

לעולם אל תריצו sudo npm install -g. זה יוצר בעיות הרשאות וסיכוני אבטחה. אם אתם נתקלים בשגיאות הרשאה עם npm, עברו ל-Native Installer.

לשדרוג התקנת npm הריצו npm install -g @anthropic-ai/claude-code@latest. הימנעו מ-npm update -g, שעלול לא להעביר אתכם לגרסה החדשה ביותר.

התקנת התוסף ל-VS Code

תוסף ה-VS Code נותן ממשק גרפי מלא ל-Claude Code בתוך ה-IDE: פאנל שיחה, תצוגת Diff זו לצד זו, אזכור קבצים עם @ ועוד. דרישה: VS Code בגרסה 1.94.0 ומעלה.

  1. פתחו את תצוגת ה-Extensions עם Ctrl+Shift+X (או Cmd+Shift+X ב-Mac).
  2. חפשו "Claude Code" (המזהה הרשמי: anthropic.claude-code) ולחצו Install.
  3. אם התוסף לא מופיע אחרי ההתקנה, הפעילו מחדש את VS Code או הריצו "Developer: Reload Window" מה-Command Palette.
  4. פתחו את הפאנל דרך אייקון ה-Spark בפינת העורך, ובפתיחה הראשונה לחצו Sign in והשלימו את ההזדהות בדפדפן.

התוסף עובד גם ב-Forks כמו Cursor, ובעורכים אחרים אפשר להתקין מ-Open VSX. שימו לב: התוסף מגיע עם עותק פרטי של ה-CLI לשימוש הפאנל בלבד, והוא אינו מוסיף את claude ל-PATH. כדי להריץ claude בטרמינל המשולב של VS Code צריך גם את ההתקנה העצמאית שתיארנו למעלה.

התקנת התוסף ל-JetBrains

תוסף ה-JetBrains (בסטטוס Beta) עובד עם IntelliJ IDEA, PyCharm, WebStorm, PhpStorm, GoLand, Android Studio ועוד. בשונה מתוסף ה-VS Code, הוא אינו כולל עותק של ה-CLI אלא מריץ את הפקודה claude בטרמינל המשולב, ולכן צריך להתקין את שני הרכיבים:

  1. התקינו קודם את ה-CLI בשיטה המתאימה למערכת שלכם (ראו למעלה). בלעדיו התוסף יציג הודעת "Cannot launch Claude Code".
  2. התקינו את התוסף "Claude Code [Beta]" מה-JetBrains Marketplace (בתוך ה-IDE: Settings, ואז Plugins, חיפוש "Claude Code").
  3. הפעילו מחדש את ה-IDE באופן מלא.
  4. הריצו claude מהטרמינל המשולב של ה-IDE, או לחצו Ctrl+Esc (ב-Mac: Cmd+Esc) לפתיחה מהירה. מטרמינל חיצוני אפשר להתחבר ל-IDE עם הפקודה /ide בתוך Session.
הערה

ב-JetBrains Remote Development יש להתקין את התוסף על המכונה המרוחקת (Settings, ואז Plugin (Host)), לא על המחשב המקומי. משתמשי WSL יכולים להגדיר בהגדרות התוסף את הפקודה wsl -d Ubuntu -- bash -lic "claude".

אפליקציית Desktop (לשונית Code)

אפליקציית Claude Desktop נותנת את Claude Code בממשק גרפי מלא, בלי טרמינל בכלל. באפליקציה שלוש לשוניות: Chat (שיחה רגילה ללא גישה לקבצים), Cowork (סוכן אוטונומי שרץ ברקע במכונה וירטואלית מבודדת) ו-Code, שהיא Claude Code אינטראקטיבי עם גישה ישירה לקבצים המקומיים שלכם.

  1. הורידו את האפליקציה: גרסת macOS אוניברסלית (Intel ו-Apple Silicon), גרסת Windows ל-x64 ול-ARM64, ו-Linux בסטטוס Beta (התקנה עם apt או קובץ .deb).
  2. התקינו, הפעילו והתחברו עם חשבון ה-Anthropic שלכם.
  3. לחצו על לשונית Code במרכז החלק העליון. אם מוצעת לכם שדרוג תוכנית, סימן שהחשבון אינו בתוכנית בתשלום.
  4. בחרו סביבה: Local (קבצים מקומיים), Cloud (תשתית הענן של Anthropic), SSH (מכונה מרוחקת) או WSL ב-Windows. ואז בחרו תיקיית פרויקט.

האפליקציה כוללת את Claude Code מובנה: אין צורך להתקין Node.js או את ה-CLI בנפרד. אם תרצו גם את הפקודה claude בטרמינל, התקינו את ה-CLI בנוסף. שימו לב: ב-Windows נדרש Git מותקן כדי ש-Sessions מקומיים יעבדו.

Claude Code on the Web Research Preview

Claude Code on the web מריץ משימות על תשתית ענן מנוהלת של Anthropic בכתובת claude.ai/code, ללא כל התקנה מקומית. השירות נמצא בסטטוס Research Preview וזמין למשתמשי Pro, Max ו-Team, ולמשתמשי Enterprise עם Premium Seats או Chat + Claude Code Seats.

איך זה עובד: כל Session רץ במכונה וירטואלית טרייה שאליה משוכפל ה-Repository שלכם מ-GitHub (החיבור נעשה דרך GitHub App או הפקודה /web-setup מהטרמינל). ה-Sessions ממשיכים לרוץ גם כשסוגרים את הדפדפן, ואפשר לעקוב אחריהם מאפליקציית המובייל של Claude. אפשר גם להעביר Session מהענן לטרמינל המקומי ובחזרה עם הדגלים --teleport ו---cloud.

מתי להשתמש: משימות מקביליות וארוכות על Repositories שמאוחסנים ב-GitHub, עבודה ממחשב שאינו שלכם, או כשאין אפשרות להתקין תוכנה. מתי לא: עבודה על קבצים מקומיים שאינם ב-GitHub, סביבות עם דרישות רשת מיוחדות, או ארגונים עם Zero Data Retention (התכונה אינה זמינה להם).

הזדהות: חיבור החשבון

תהליך ההתחברות

בהרצה הראשונה של claude תתבקשו להתחבר. Claude Code פותח חלון דפדפן להזדהות; אם הדפדפן לא נפתח אוטומטית, לחצו על המקש c כדי להעתיק את כתובת ההתחברות ולהדביק אותה בדפדפן ידנית. בסביבות כמו WSL2, SSH או Containers, הדפדפן עשוי להציג קוד התחברות במקום לחזור לטרמינל אוטומטית; הדביקו את הקוד בטרמינל בשורת Paste code here if prompted. בסיום מוצג Login successful.

אפשר להתחבר גם מהטרמינל בלי לפתוח Session, עם פקודת המשנה הייעודית:

$ claude auth login (נפתח דפדפן להזדהות; בסיום מוצג אישור התחברות)

הדגלים הזמינים: --email למילוי מראש של כתובת המייל, --sso לכפיית הזדהות SSO, ו---console להתחברות עם חשבון Console (חיוב API) במקום מנוי. בתוך Session פעיל משתמשים ב-/login להחלפת חשבון וב-/logout להתנתקות. הפקודה /status מציגה איזו שיטת הזדהות פעילה כרגע.

מנוי מול חיוב API: מה ההבדל

שני מסלולי חיוב עיקריים:

  • מנוי (Subscription): התחברות עם חשבון Claude.ai בתוכנית Pro, Max, Team או Enterprise. השימוש ב-Claude Code כלול במחיר המנוי, עם מכסות שימוש שמתאפסות מחזורית לפי התוכנית. זה המסלול המומלץ לרוב המשתמשים.
  • Claude Console (חיוב API): התחברות עם חשבון Console ותשלום לפי צריכת Tokens בפועל (קרדיטים בתשלום מראש). בהתחברות הראשונה נוצר אוטומטית Workspace בשם "Claude Code" ב-Console למעקב עלויות מרוכז. מתאים לארגונים שרוצים חיוב לפי שימוש, ולתרחישי אוטומציה.

זמינות Claude Code בתוכניות, נכון ל-28.07.2026 לפי עמוד התמחור הרשמי claude.com/pricing: התוכנית החינמית אינה כוללת Claude Code. תוכנית Pro (17 דולר לחודש במסלול שנתי, 20 דולר במסלול חודשי) כוללת Claude Code. תוכנית Max (החל מ-100 דולר לחודש, עם מסלולי שימוש של פי 5 או פי 20) כוללת Claude Code. תוכנית Team (20 דולר למשתמש לחודש במסלול שנתי, 25 דולר במסלול חודשי) כוללת Claude Code, ותוכנית Enterprise (מחיר Seat בתוספת שימוש בתעריפי API, בחיוב שנתי) כוללת Claude Code. המחירים משתנים מעת לעת; בדקו את העמוד הרשמי לפני החלטה.

אזהרה: משתנה סביבה שדורס את המנוי

אם משתנה הסביבה ANTHROPIC_API_KEY מוגדר אצלכם (למשל מפרויקט ישן), הוא עשוי לגבור על הזדהות המנוי לאחר שתאשרו אותו, ואף לגרום לשגיאות אם המפתח שייך לארגון שנחסם. הריצו unset ANTHROPIC_API_KEY ובדקו עם /status איזו שיטה פעילה.

claude setup-token: אסימון לאוטומציה

לסביבות שבהן אין דפדפן, כמו CI וסקריפטים, הפקודה claude setup-token מייצרת אסימון OAuth ארוך טווח (שנה). הפקודה פותחת את אותו תהליך הזדהות בדפדפן, מדפיסה את האסימון לטרמינל ואינה שומרת אותו בשום מקום. העתיקו אותו והגדירו אותו כמשתנה סביבה:

$ claude setup-token (נפתח דפדפן לאישור; האסימון מודפס לטרמינל) $ export CLAUDE_CODE_OAUTH_TOKEN=YOUR_TOKEN_HERE

האסימון מזוהה עם המנוי שלכם ודורש תוכנית Pro, Max, Team או Enterprise.

איפה נשמרים פרטי ההזדהות: ב-macOS ב-Keychain המוצפן; ב-Linux בקובץ ~/.claude/.credentials.json עם הרשאות 0600; ב-Windows בקובץ %USERPROFILE%\.claude\.credentials.json המוגן בהרשאות פרופיל המשתמש.

בדיקת גרסה, עדכון והסרה

בדיקת גרסה ואבחון

$ claude --version 2.1.211 (Claude Code) $ claude doctor (אבחון לקריאה בלבד: תקינות ההתקנה, שגיאות בקובצי הגדרות, אזהרות והצעות תיקון)

claude doctor מדפיס אבחון מלא בלי לפתוח Session: בריאות ההתקנה, התקנות כפולות, בעיות PATH, שגיאות בקובצי הגדרות ותוצאת ניסיון העדכון האחרון. הוא לקריאה בלבד ואינו משנה דבר, ולכן בטוח להריץ אותו בכל שלב. בתוך Session קיימת גם הפקודה /doctor, שמאבחנת לעומק (כולל התקנות כפולות, Hooks איטיים ותצורה לא מנוצלת) ויכולה גם להציע ולהחיל תיקונים, תמיד באישורכם ואחרי הצגת הממצאים.

עשו לעצמכם הרגל: אחרי כל התקנה, שדרוג או שינוי תצורה משמעותי, הריצו claude doctor. רוב הבעיות שנראה בסעיף ה-Troubleshooting בהמשך מאובחנות שם בשורה אחת ברורה, הרבה לפני שהן הופכות לתקלה מסתורית באמצע עבודה.

עדכונים

התקנות Native מתעדכנות אוטומטית ברקע: Claude Code בודק עדכונים בהפעלה ומדי פעם תוך כדי ריצה, מוריד ומתקין ברקע, והגרסה החדשה נכנסת לתוקף בהפעלה הבאה. לעדכון ידני מיידי:

$ claude update Successfully updated from 2.1.205 to version 2.1.211

אם אתם כבר בגרסה האחרונה יוצג Claude Code is up to date (<version>). אפשר לשלוט בערוץ העדכונים דרך ההגדרה autoUpdatesChannel עם הערכים "latest" (ברירת מחדל, כל גרסה מיד) או "stable" (בדרך כלל שבוע מאחור, מדלג על רגרסיות), ולבטל עדכונים אוטומטיים עם DISABLE_AUTOUPDATER:

~/.claude/settings.json
{
  "autoUpdatesChannel": "stable",
  "env": { "DISABLE_AUTOUPDATER": "1" }
}

התקנות Homebrew, WinGet, apt, dnf ו-apk אינן מתעדכנות אוטומטית כברירת מחדל; עדכנו בכלי החבילות המתאים.

הסרה והתקנה מחדש

להסרת התקנת Native:

Bash (macOS / Linux / WSL)
rm -f ~/.local/bin/claude
rm -rf ~/.local/share/claude
PowerShell (Windows)
Remove-Item -Path "$env:USERPROFILE\.local\bin\claude.exe" -Force
Remove-Item -Path "$env:USERPROFILE\.local\share\claude" -Recurse -Force

להסרת התקנות אחרות: brew uninstall --cask claude-code, winget uninstall Anthropic.ClaudeCode, sudo apt remove claude-code או npm uninstall -g @anthropic-ai/claude-code, לפי שיטת ההתקנה. התקנה מחדש היא פשוט הרצה חוזרת של פקודת ההתקנה. אם אחרי הסרה הפקודה claude עדיין עובדת, כנראה קיימת התקנה שנייה או Alias ישן; ראו "Check for conflicting installations" בתיעוד פתרון התקלות.

אזהרה

מחיקת התיקייה ~/.claude והקובץ ~/.claude.json מוחקת את כל ההגדרות, ההרשאות שאושרו, הגדרות ה-MCP והיסטוריית ה-Sessions. עשו זאת רק אם אתם באמת רוצים איפוס מלא, ורק אחרי הסרת תוסף ה-IDE ואפליקציית ה-Desktop, שאחרת ייצרו את התיקייה מחדש.

נגישות: Screen Reader Mode והגדרות נלוות

למי שעובד עם קורא מסך (VoiceOver, NVDA), ל-Claude Code יש Screen Reader Mode ייעודי (מגרסה 2.1.181): במקום ממשק Terminal חזותי עם מסגרות, אנימציות וציור מחדש, המצב מדפיס טקסט ליניארי עם תוויות קבועות בתחילת כל הודעה (you:, claude:, tool:, error:, Permission Required:), תפריטים הופכים לרשימות ממוספרות שעונים עליהן בהקלדת מספר, ופעמון ה-Terminal מצלצל כשנדרשת תשומת לבכם. שלוש דרכים להפעלה, לפי סדר עדיפות: ל-Session בודד claude --ax-screen-reader; ל-Shell נוכחי export CLAUDE_AX_SCREEN_READER=1 (ב-PowerShell: $env:CLAUDE_AX_SCREEN_READER = "1"); לכל המכונה "axScreenReader": true בקובץ ההגדרות של המשתמש (פרק 17). בהפעלה מודפסת שורת אישור בסגנון [Screen Reader Mode: on via flag]. המצב אינו מופעל אוטומטית כשקורא מסך רץ, ואינו משנה את מצב -p, שממילא מדפיס טקסט פשוט.

מעבר לקורא מסך: CLAUDE_CODE_ACCESSIBILITY=1 משאיר את סמן ה-Terminal גלוי כדי שמגדילי מסך יעקבו אחריו; ההגדרה prefersReducedMotion מצמצמת אנימציות; וההגדרה theme (או /theme) כוללת ערכות ידידותיות לעיוורי צבעים (dark-daltonized, light-daltonized). מקור: Use Claude Code with a screen reader (נבדק: 29.07.2026).

Proxy, Firewall וסביבות ארגוניות

אם אתם מאחורי Proxy ארגוני, Claude Code מכבד את משתני הסביבה הסטנדרטיים (אין תמיכה ב-SOCKS Proxy):

Bash
export HTTPS_PROXY=https://proxy.example.com:8080
export HTTP_PROXY=http://proxy.example.com:8080
export NO_PROXY="localhost,192.168.1.1,.example.com"

ב-Proxy שמבצע TLS Inspection עם תעודת CA ארגונית, הגדירו export NODE_EXTRA_CA_CERTS=/path/to/corporate-ca.pem כדי ש-Claude Code יסמוך על התעודה. ברירת המחדל היא אמון גם בחבילת התעודות המובנית וגם במאגר של מערכת ההפעלה (ההגדרה CLAUDE_CODE_CERT_STORE שולטת בכך), וקיימת גם תמיכה ב-mTLS עם תעודת לקוח.

הדומיינים המרכזיים שיש לאשר ב-Firewall או ב-Proxy (הרשימה המלאה והמעודכנת בעמוד network-config בתיעוד):

בסביבות מנוהלות, מנהלי מערכת יכולים לאכוף הגדרות דרך Managed Settings, לקבוע ערוץ עדכונים אחיד, להגביל התחברות לארגון מסוים ועוד. נושא הפריסה הארגונית המלאה, כולל Managed Settings, מדיניות הרשאות ו-Cloud Providers כמו Amazon Bedrock, מכוסה בהרחבה בפרק 29.

Troubleshooting: תקלות התקנה נפוצות

1. הפקודה claude לא נמצאת (בעיית PATH)

תסמינים: ההתקנה הסתיימה בהצלחה, אבל claude מחזיר command not found: claude (ב-macOS/Linux) או 'claude' is not recognized (ב-Windows).

סיבה: תיקיית ההתקנה (~/.local/bin או %USERPROFILE%\.local\bin) אינה ב-PATH של ה-Shell.

תיקון ב-Bash/Zsh:

Bash / Zsh
# Zsh (ברירת המחדל ב-macOS):
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
# Bash (ברירת המחדל ברוב הפצות Linux):
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

תיקון ב-PowerShell:

PowerShell
$currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$currentPath;$env:USERPROFILE\.local\bin", 'User')

אימות: פתחו טרמינל חדש והריצו claude --version. שימו לב: אם התקנתם רק את תוסף ה-VS Code, הפקודה claude לא תהיה זמינה בטרמינל כלל; התקינו גם את ה-CLI העצמאי.

2. פקודת התקנה שגויה ל-Shell הלא נכון ב-Windows

תסמינים: 'irm' is not recognized, או The token '&&' is not a valid statement separator, או A parameter cannot be found that matches parameter name 'fsSL', או 'bash' is not recognized.

סיבה: הרצתם פקודת התקנה שמיועדת ל-Shell אחר: פקודת PowerShell ב-CMD, פקודת CMD ב-PowerShell, או את פקודת ה-Bash של Linux על Windows.

תיקון: זהו את ה-Shell לפי תחילת השורה (PS C:\ פירושו PowerShell) והריצו את הפקודה המתאימה מהסעיפים למעלה.

אימות: claude --version בטרמינל חדש.

3. Windows חוסם סקריפטים: running scripts is disabled

תסמינים: בהתקנה או בהרצה דרך npm על Windows מתקבל SecurityError עם ההודעה ...cannot be loaded because running scripts is disabled on this system.

סיבה: מדיניות ה-Execution Policy של PowerShell חוסמת קובצי .ps1 ש-npm יוצר. שימו לב שהמדיניות אינה משפיעה על מתקין ה-PowerShell הרשמי (irm ... | iex), שמריץ טקסט ולא קובץ סקריפט.

תיקון:

PowerShell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

חלופות: קריאה ל-claude.cmd במקום claude, או מעבר ל-Native Installer שמתקין קובץ בינארי ולא סקריפט.

אימות: claude --version בחלון PowerShell חדש.

4. סקריפט ההתקנה מחזיר HTML או שגיאת 403

תסמינים: syntax error near unexpected token '<' ואחריו <!DOCTYPE html>, או curl: (22) The requested URL returned error: 403, או ב-PowerShell שגיאות Parse שמצטטות תגיות HTML.

סיבה: כתובת ההתקנה החזירה עמוד HTML או שגיאה במקום הסקריפט. אם העמוד אומר "App unavailable in region", Claude Code אינו זמין במדינה שלכם. אחרת מדובר בדרך כלל ב-Proxy או Firewall ארגוני שחוסם, או בתקלה זמנית.

תיקון: בדקו קישוריות עם curl -sI https://downloads.claude.ai/claude-code-releases/latest (ב-PowerShell: curl.exe -sI). תשובת 200 אומרת שהשרת נגיש והכשל היה זמני; נסו שוב. אחרת נסו שיטת התקנה חלופית: brew install --cask claude-code ב-macOS או winget install Anthropic.ClaudeCode ב-Windows, או עברו דרך ה-Proxy עם משתני HTTPS_PROXY.

אימות: claude --version.

5. שגיאות TLS/SSL, כולל Proxy ארגוני עם תעודה עצמית

תסמינים: curl: (35) TLS connect error, או Could not establish trust relationship for the SSL/TLS secure channel ב-PowerShell, או unable to get local issuer certificate / SELF_SIGNED_CERT_IN_CHAIN.

סיבה: כשל בלחיצת יד TLS: תעודות מערכת לא מעודכנות, גרסת TLS ישנה, או Proxy ארגוני שמבצע TLS Inspection עם תעודת CA משלו.

תיקון: עדכנו תעודות מערכת (sudo apt-get update && sudo apt-get install ca-certificates ב-Ubuntu/Debian). ב-Windows אפשרו TLS 1.2 לפני ההתקנה:

PowerShell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
irm https://claude.ai/install.ps1 | iex

מאחורי Proxy עם תעודה ארגונית, העבירו ל-curl את חבילת ה-CA בהתקנה, ולאחר מכן הגדירו את המשתנה לריצה השוטפת:

Bash
curl --cacert /path/to/corporate-ca.pem -fsSL https://claude.ai/install.sh | bash
export NODE_EXTRA_CA_CERTS=/path/to/corporate-ca.pem

אימות: claude --version, ואחריו פתיחת Session ושליחת Prompt קצר לוודא שגם תעבורת ה-API עוברת.

6. שגיאות npm: גרסת Node ישנה או בעיות הרשאה

תסמינים: אזהרת EBADENGINE בזמן npm install, או שגיאות הרשאה (EACCES) בהתקנה גלובלית, או Error: claude native binary not installed בהרצה.

סיבה: חבילת ה-npm דורשת Node.js 22 ומעלה (על גרסה ישנה יותר תוצג אזהרת EBADENGINE, אך ההתקנה בדרך כלל תושלם כי הבינארי אינו תלוי ב-Node בזמן ריצה). שגיאות הרשאה נובעות מתיקיית npm גלובלית שאינה ניתנת לכתיבה. השגיאה על Binary חסר מופיעה כשמותקנים עם --omit=optional או --ignore-scripts.

תיקון: הפתרון הפשוט והמומלץ הוא לעבור ל-Native Installer: curl -fsSL https://claude.ai/install.sh | bash. אם חייבים npm: עדכנו Node ל-22+, אל תשתמשו ב-sudo, והתקינו בלי הדגלים שמדלגים על Optional Dependencies וסקריפטים.

אימות: claude --version ואז claude doctor.

7. בעיות WSL: node not found או Exec format error

תסמינים: בתוך WSL: exec: node: not found בהרצת claude (בהתקנת npm), או cannot execute binary file: Exec format error.

סיבה: WSL מייבא את ה-PATH של Windows, ולכן עלול להשתמש ב-Node/npm של Windows (נתיבים שמתחילים ב-/mnt/c/) במקום אלה של Linux. שגיאת Exec format error מעידה שאתם על WSL1, שיש בו רגרסיה ידועה עם הבינארי.

תיקון: בדקו עם which npm ו-which node; אם הנתיבים מתחילים ב-/mnt/c/, התקינו Node דרך מנהל החבילות של ההפצה או דרך nvm בתוך WSL. ל-WSL1: שדרגו עם wsl --set-version <DistroName> 2 מ-PowerShell. ועדיף מכול: השתמשו ב-Native Installer בתוך WSL, שאינו תלוי ב-Node.

אימות: claude --version בתוך טרמינל ה-WSL.

8. ההתחברות בדפדפן נכשלת (WSL2, SSH, שרתים מרוחקים)

תסמינים: הדפדפן לא נפתח בזמן ההתחברות, או שההתחברות בדפדפן מסתיימת אך הטרמינל לא ממשיך, או OAuth error: Invalid code.

סיבה: בסביבה מרוחקת הדפדפן נפתח על מכונה אחרת, וההפניה חזרה אינה מגיעה לשרת ההאזנה המקומי של Claude Code. קוד שפג תוקפו או הועתק חלקית גורם לשגיאת Invalid code.

תיקון: לחצו c בטרמינל כדי להעתיק את כתובת ההתחברות ופתחו אותה בדפדפן במחשב המקומי. בסיום, הדביקו את הקוד שמוצג בדפדפן בשורת Paste code here if prompted. אם ההדבקה לא נקלטת, השתמשו ב-claude auth login שקורא את הקוד מהקלט הסטנדרטי. ב-WSL2 אפשר גם להגדיר export BROWSER="/mnt/c/Program Files/Google/Chrome/Application/chrome.exe" כדי שהדפדפן של Windows ייפתח. במקרה כישלון כללי: /logout, סגירה, והתחברות מחדש.

אימות: הופעת Login successful, ואז /status בתוך Session להצגת החשבון הפעיל.

אימות: איך יודעים שהסביבה מוכנה

הריצו את שלוש הבדיקות הבאות. אם שלושתן עוברות, הסביבה שלכם תקינה:

  1. claude --version מדפיס מספר גרסה ואחריו (Claude Code).
  2. claude doctor רץ עד הסוף בלי שגיאות Critical (אזהרות קלות מקובלות).
  3. הרצת claude בתיקיית פרויקט כלשהי פותחת Session, מציגה את הגרסה, המודל ותיקיית העבודה מעל שורת הקלט, ו-Prompt ראשון כמו what can Claude Code do? מקבל תשובה.
  • Claude Code מותקן בשיטה המתאימה למערכת ההפעלה.
  • claude --version עובד מטרמינל חדש (ה-PATH תקין).
  • ההתחברות הושלמה והפקודה /status מציגה את החשבון הנכון.
  • ידוע לכם איך מתעדכנים (אוטומטית או עם claude update).
  • אם אתם מאחורי Proxy: משתני הסביבה מוגדרים והדומיינים מאושרים.

תרגיל

תרגיל 2.1: התקנה מלאה ואימות

בצעו את הרצף הבא במערכת שלכם:

  1. התקינו את Claude Code בשיטה המומלצת למערכת ההפעלה שלכם.
  2. ודאו את הגרסה עם claude --version ורשמו לעצמכם את המספר.
  3. הריצו claude doctor וקראו את הפלט. האם יש אזהרות? מה הן אומרות?
  4. הריצו claude בתיקייה ריקה חדשה, השלימו את ההתחברות, ושלחו את ה-Prompt: what can Claude Code do?
  5. צאו עם /exit, ואז הריצו claude update ובדקו מה הפלט.
פתרון מוסבר

שלב 1: על macOS/Linux/WSL הפקודה היא curl -fsSL https://claude.ai/install.sh | bash, ועל Windows ב-PowerShell: irm https://claude.ai/install.ps1 | iex. שלב 2: פלט תקין נראה כמו 2.1.211 (Claude Code); המספר אצלכם יהיה עדכני יותר. שלב 3: claude doctor אמור לדווח על התקנה תקינה; אזהרה שכיחה אצל מי שהתקין בעבר דרך npm היא התקנה כפולה, והפתרון הוא הסרת ההתקנה הישנה. שלב 4: בהרצה הראשונה ייפתח דפדפן להתחברות, ואחרי האישור יוצג Login successful. מכיוון שהתיקייה ריקה, התשובה ל-Prompt תתאר את יכולות Claude Code באופן כללי. שלב 5: אם ההתקנה טרייה, claude update ידפיס שאתם בגרסה העדכנית: Claude Code is up to date (<version>). אם דווקא הותקן עדכון, יוצג Successfully updated from ... to version ....
