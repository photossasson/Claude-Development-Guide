Final Capstone: TaskFlow v1.0

זהו פרויקט הסיום של המדריך. צוות קטן צריך לשחרר את TaskFlow v1.0: אימות משתמשים, תגובות על משימות, תזכורות לתאריכי יעד ויומן ביקורת (Audit log), עם CI ירוק, תיעוד מעודכן ועמדת אבטחה מוגדרת. הפרק מגדיר את התרחיש, הדרישות, המגבלות ואבני הדרך; מפרט את ה-Skills, ה-CLAUDE.md, הבדיקות ודרישות האבטחה; ואז מציג פתרון מלא, אבן דרך אחר אבן דרך, עם ה-Prompts, ההחלטות המרכזיות, תוצאות להמחשה ופקודות האימות. בסוף: רשימת בדיקה למנחה, שיפורים מוצעים וסיכום המסע של המדריך כולו. כל מה שמופיע כאן משתמש רק ביכולות ובפקודות שאומתו בפרקים הקודמים.

התרחיש

אתם צוות של שלושה: מפתחת Backend, מפתח Frontend ומוביל טכני שגם אחראי על אבטחה ושחרור. TaskFlow (examples/taskflow) הוא כרגע אפליקציית משימות בסיסית: CRUD על משימות עם שלושה סטטוסים, בלי משתמשים, בלי תאריכים, בלי היסטוריה. הלקוח הפנימי מבקש גרסה 1.0 שאפשר להעמיד לצוות של 20 איש: כל אחד נכנס עם שם משתמש וסיסמה, מגיב על משימות, מקבל תזכורת על משימות שמועדן מתקרב, והמנהלים רואים מי עשה מה ומתי. יש לכם שבועיים, ואתם עובדים עם Claude Code לפי כללי המדריך: תכנון לפני יישום, שינויים קטנים עם ראיות, סקירה בהקשר נקי, בלי bypass.

המטרה הפדגוגית: להפעיל יחד את כל מה שנלמד. לא כל אבן דרך דורשת את כל הכלים, אבל בסוף הפרויקט תהיו חייבים להראות שימוש מושכל ב-Plan Mode, CLAUDE.md, Settings והרשאות, Hooks, Skills, Subagents, Git ו-PRs, בדיקות, CI, סקירת אבטחה, ניהול Context ועלות, ותיעוד.

איך ניגשים לפרויקט: ארבעה שערים בכל אבן דרך

לפני הדרישות, ההרגל. כל אבן דרך בפתרון עוברת את אותם ארבעה שערים, וזה מה שהופך את הפרויקט מ"עבודה עם Claude" ל"עבודה מקצועית עם Claude":

  1. שער התכנון. ה-Session נפתח ב-Plan Mode (Shift+Tab או claude --permission-mode plan). Claude קורא, שואל, ומציע תוכנית עם קבצים, סדר ובדיקות. אתם עורכים ומאשרים. אין שורת קוד לפני האישור. הסיבה, לפי התיעוד הרשמי: קפיצה ישירה לקוד פותרת לעיתים קרובות את הבעיה הלא נכונה.
  2. שער הצעדים הקטנים. היישום נעשה בצעדים שכל אחד מסתיים בבדיקה שאפשר להריץ (pytest -q, npm run typecheck). Claude מציג Diff ומחכה. אם צעד נוגע בקובץ לא צפוי, עוצרים.
  3. שער הסקירה בהקשר נקי. לפני PR, מישהו שלא כתב את הקוד סוקר אותו: Subagent עם Context Window משלו, /code-review המובנה, או Session שני. אחר כך אדם.
  4. שער הראיות. "גמור" פירושו פלט בדיקות, פלט CI, ורשומה ב-PR של מה שנבדק. הצהרה בלי ראיה לא נספרת.

בין אבני דרך: /usage לבדיקת תקציב, Handoff קצר אם ה-Session ארוך, ו-/clear. הכלל מהתיעוד: אחרי שני תיקונים כושלים על אותה בעיה, לא מנסים שלישי באותו Session; פותחים חדש עם Prompt טוב יותר. הפתרון למטה מציין איפה הכלל הזה הופעל בפועל.

דרישות

דרישות פונקציונליות

  1. אימות (Auth). הרשמה (POST /auth/register), כניסה (POST /auth/login) שמחזירה Token, יציאה (POST /auth/logout), ו-GET /auth/me. כל Endpoint של משימות דורש Token תקף. שני תפקידים: member ו-admin. סיסמאות נשמרות רק כ-Hash.
  2. תגובות (Comments). POST /tasks/{id}/comments, GET /tasks/{id}/comments, DELETE /comments/{id} (רק המחבר או admin). תגובה: 1 עד 2000 תווים. אזכורים @username נשמרים בטבלת comment_mentions (כמו ב-פרק 34). לרשימת המשימות מתווסף comment_count.
  3. תזכורות (Due-date reminders). שדה due_date אופציונלי (ISO 8601, UTC) על משימה; דחייה של תאריך בעבר ביצירה; GET /tasks?due_before=; ופקודת CLI python -m app.reminders --hours 24 שמדפיסה את המשימות שמועדן בתוך החלון ורושמת אותן בטבלת reminders_sent כדי לא לשלוח פעמיים. הפעלה מתוזמנת ב-GitHub Actions (schedule) או cron.
  4. יומן ביקורת (Audit log). כל יצירה, עדכון ומחיקה של משימה או תגובה, וכל כניסה, נרשמים ב-audit_log: actor, action, entity_type, entity_id, at, details (JSON קצר). GET /audit?limit=&since= ל-admin בלבד. הרשומות אינן ניתנות לעריכה או מחיקה דרך ה-API.
  5. Frontend. מסך כניסה, רשימת משימות עם due_date ומונה תגובות, פאנל תגובות למשימה, ומסך Audit ל-admin. TypeScript strict, ללא any.

דרישות לא-פונקציונליות

  • כל הבדיקות עוברות: cd backend && pytest -q, cd frontend && npm run typecheck. כיסוי Backend על מודולי auth, comments, reminders, audit: לפחות 85% (נמדד עם pytest --cov אם מותקן; אחרת דוח ידני לפי מקרים).
  • CI ירוק על main ועל כל PR; ה-Workflow הקיים מורחב, לא מוחלף.
  • אין סודות ב-Repository; .env ב-.gitignore; משתני סביבה מתועדים ב-README.
  • כל שינוי בהתנהגות מלווה בעדכון README; החלטות ארכיטקטוניות ב-docs/adr/.
  • ביצועים: GET /tasks עם comment_count בשאילתה אחת (בלי N+1); כל Endpoint רשימה עם limit ברירת מחדל 100.

CLAUDE.md (v1.0)
# TaskFlow

Small full-stack task manager. Version 1.0 adds auth, comments, due-date reminders and an audit log.

## Structure
- `backend/`: Python 3.12, FastAPI, SQLite (stdlib sqlite3, no ORM). Entry: `app/main.py`.
  - `app/routers/`: `tasks.py`, `auth.py`, `comments.py`, `audit.py`
  - `app/auth.py`: password hashing (hashlib.scrypt) and session tokens (secrets)
  - `app/audit.py`: `record(actor, action, entity_type, entity_id, details)`; call it in every mutating route
  - `app/reminders.py`: CLI `python -m app.reminders --hours N`
- `frontend/`: React 18 + TypeScript + Vite. Entry: `src/App.tsx`. API client: `src/api.ts`. Types: `src/types.ts`.
- `docs/adr/`: architecture decision records. Add one for every dependency or schema decision.

## Commands
- Backend tests: `cd backend && pytest -q`
- Backend dev server: `cd backend && uvicorn app.main:app --reload`
- Frontend typecheck: `cd frontend && npm run typecheck`
- Reminders (dry run): `cd backend && TASKFLOW_DB=taskflow.db python -m app.reminders --hours 24 --dry-run`

## Conventions
- Python: type hints everywhere; no ORM; parameterized SQL only (never f-strings with user input).
- TypeScript: strict mode; no `any`.
- Task status values: `todo`, `in_progress`, `done` (single source of truth: backend CHECK constraint + `TaskStatus` type).
- Dates are ISO 8601 strings in UTC. `due_date` is optional and must not be in the past on create.
- Auth: every route except `/health` and `/auth/register|login` requires `Authorization: Bearer <token>`. Roles: `member`, `admin`.
- Audit: every create/update/delete of a task or comment and every login calls `audit.record(...)`. Audit rows are append-only.
- Errors: FastAPI HTTPException with `{"detail": "..."}`; 401 unauthenticated, 403 forbidden, 404 not found, 422 validation.
- Never weaken or delete a failing test to make it pass; report it instead.

## Environment variables
- `TASKFLOW_DB`: SQLite path (tests set a temp file).
- `TASKFLOW_TOKEN_TTL_HOURS`: session token lifetime, default 24.

## Workflow rules
- Plan first for anything touching more than one file; small steps with diffs; run tests after each step.
- New dependency = ADR first.
- Do not edit `.env*`, `.github/workflows/*` or `backend/tests/*` without saying so explicitly in the response.
- When compacting, always preserve the list of modified files, the current test status and open decisions.

## Definition of Done
- Tests pass, typecheck passes, no secrets in code, README updated when behavior changes, ADR added for architectural decisions.

import hashlib, hmac, os, secrets
from datetime import datetime, timedelta, timezone

def hash_password(password: str) -> str:
    salt = os.urandom(16)
    digest = hashlib.scrypt(password.encode(), salt=salt, n=2**14, r=8, p=1)
    return salt.hex() + "$" + digest.hex()

def verify_password(password: str, stored: str) -> bool:
    salt_hex, digest_hex = stored.split("$", 1)
    digest = hashlib.scrypt(password.encode(), salt=bytes.fromhex(salt_hex), n=2**14, r=8, p=1)
    return hmac.compare_digest(digest.hex(), digest_hex)

def new_token() -> str:
    return secrets.token_urlsafe(32)

def hash_token(token: str) -> str:
    return hashlib.sha256(token.encode()).hexdigest()

def expiry(hours: int) -> str:
    return (datetime.now(timezone.utc) + timedelta(hours=hours)).isoformat()

import json, sqlite3
from typing import Any, Optional

REDACT = {"password", "token", "authorization"}

def record(conn: sqlite3.Connection, actor: str, action: str,
           entity_type: str, entity_id: Optional[int],
           details: Optional[dict[str, Any]] = None) -> None:
    safe = {k: v for k, v in (details or {}).items() if k.lower() not in REDACT}
    conn.execute(
        "INSERT INTO audit_log (actor, action, entity_type, entity_id, details) VALUES (?, ?, ?, ?, ?)",
        (actor, action, entity_type, entity_id, json.dumps(safe)),
    )

אם יש משפט אחד לקחת מהמדריך, הוא זה: Claude Code הוא סוכן שעובד הכי טוב כשנותנים לו הקשר מדויק, גבולות ברורים ודרך לבדוק את עצמו, וכשאתם נשארים בעמדת הבקרה: מתכננים לפני, סוקרים בהקשר נקי אחרי, ומודדים תמיד. TaskFlow v1.0 הוא ההוכחה שאפשר לעשות את זה בשבועיים, בלי לוותר על אבטחה, על בדיקות או על תיעוד. עכשיו תורכם, על הפרויקט שלכם.
