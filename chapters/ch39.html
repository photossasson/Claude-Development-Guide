Troubleshooting מקיף

הפרק הזה הוא מדריך העזרה הראשונה של כל המדריך. הוא אוסף, לפי תחומים, את התקלות שנתקלים בהן בעבודה יומיומית עם Claude Code: התקנה, אימות, זמינות Models, הרשאות, Context, איטיות, פקודות, Skills, Hooks, MCP, Connectors, Subagents, Plugins, IDE, Git, בדיקות, CI, עלות ורשת ארגונית. כל תקלה מוצגת באותו מבנה אחיד: תסמינים, סיבות אפשריות, פקודות אבחון, תיקון צעד אחר צעד, אימות ומניעה. אפשר לקרוא אותו ברצף, אבל הוא בנוי כך שתפתחו אותו כשמשהו נשבר, תמצאו את הבלוק הרלוונטי תוך דקה, ותחזרו לעבודה. כל הפקודות אומתו מול התיעוד הרשמי בתאריך 29.07.2026.

איך להשתמש בפרק הזה

ב-Claude Code יש שכבות רבות שיכולות להשתבש: הבינארי המותקן, פרטי ההתחברות, הרשת, ה-Model שנבחר, קובצי ההגדרות (בארבע רמות), CLAUDE.md, Skills, Hooks, שרתי MCP, Plugins וה-IDE. העיקרון שמנחה את כל הפרק הוא בידוד: לפני שמנסים לתקן, מזהים באיזו שכבה הבעיה, ורק אז מטפלים. לכן הפרק נפתח ברשימת Triage אוניברסלית של חמש דקות, ממשיך בטבלת החלטה שמפנה מכל תסמין לבלוק המתאים ולפרק הרלוונטי במדריך, ורק אחר כך יורד לפרטים לפי תחום.

המונחים בפרק מניחים שקראתם את הפרקים הרלוונטיים (למשל, פרק 17 על Settings ו-פרק 18 על Permission Modes). כשבלוק מסתמך על ידע מפרק אחר, יש קישור. הפרק אינו מחליף את דף התיעוד הרשמי של שגיאות (Error reference) שמפרט מאות מחרוזות שגיאה מדויקות; הוא מרכז את המקרים השכיחים ומסביר את הדרך לחשוב עליהם.

הערה על מבנה הבלוקים

כל תקלה מופיעה כטבלה בעלת שש שורות קבועות: תסמינים (מה רואים), סיבות אפשריות (מהסבירה לפחות סבירה), פקודות אבחון (מה מריצים כדי לאשר את הסיבה), תיקון צעד אחר צעד, אימות (איך יודעים שהתקלה נפתרה) ו-מניעה (איך לא לחזור לשם). פקודות שמתחילות ב-/ רצות בתוך Session פעיל; פקודות שמתחילות ב-claude רצות ב-Terminal מחוץ ל-Session.

חמש הדקות הראשונות: Triage אוניברסלי

לפני שצוללים לתחום מסוים, עברו על הרשימה הבאה לפי הסדר. ברוב המקרים היא מבודדת את השכבה הבעייתית או פותרת את התקלה ישירות. כל צעד לוקח שניות.

  • הריצו claude --version. אם הפקודה לא נמצאת, הבעיה היא התקנה או PATH (ראו התקנה). אם הגרסה ישנה מהצפוי, הריצו claude update.
  • הריצו claude doctor מה-Terminal. זו בדיקה לקריאה בלבד: תקינות התקנה, שגיאות בקובצי Settings, התקנות כפולות, ו-Search (ripgrep). קראו כל שורה שאינה OK.
  • בתוך Session, הריצו /status: אילו מקורות הגדרות פעילים, האם יש Managed Settings, איזו שיטת אימות פעילה, איזה Model, ואילו Proxy ותעודות נטענו.
  • הריצו /doctor בתוך ה-Session: בניגוד ל-claude doctor, זה גם מציע תיקונים ומחיל אותם רק אחרי אישורכם.
  • הריצו /context: האם CLAUDE.md, Skills, MCP tools ו-Subagents נטענו בכלל, וכמה מה-Context Window תפוס.
  • לפי התחום, הריצו את פקודת התצפית הייעודית: /permissions, /hooks, /mcp, /skills, /memory, /usage.
  • אם עדיין לא ברור, הפעילו Session נקי מהתאמות אישיות: claude --safe-mode. אם הבעיה נעלמת, האשם הוא CLAUDE.md, Skill, Plugin, Hook או שרת MCP. אם לא, הבעיה בהתקנה, באימות, ברשת או ב-Managed Settings.
  • לבידוד מוחלט: cd /tmp && CLAUDE_CONFIG_DIR=/tmp/claude-clean claude. אתם אמורים לראות את מסכי ההגדרה הראשונית. אם התקלה נמשכת גם כאן, היא מחוץ להגדרות שלכם.
  • לתיעוד מלא: claude --debug-file /tmp/claude.log ואז tail -f /tmp/claude.log ב-Terminal שני. בתוך Session קיים, /debug מדליק רישום ומבקש מ-Claude לאבחן לפי הלוג.
  • בדקו את status.claude.com אם השגיאה היא 5xx, 529 Overloaded או ניתוקים חוזרים.
$ claude --version 2.1.220 (Claude Code) $ claude doctor Installation: OK (native, ~/.local/bin/claude) Settings: OK Search: OK (bundled) $ claude auth status --text Logged in (claude.ai subscription)

הפלט המדויק של claude doctor משתנה בין גרסאות; מה שחשוב הוא לקרוא כל שורה שאינה תקינה. claude auth status מחזיר קוד יציאה 0 כשמחוברים ו-1 כשלא, ולכן הוא מתאים גם לסקריפטים.

אזהרה: --safe-mode אינו --bare

--safe-mode מכבה התאמות אישיות אבל שומר על אימות, בחירת Model, כלים מובנים והרשאות. --bare (פרק 33) הוא מצב מינימלי להרצה לא-אינטראקטיבית. לאבחון תקלות השתמשו ב---safe-mode. שימו לב ש-Managed Settings של הארגון (כולל Hooks מנוהלים) ממשיכים לחול גם ב---safe-mode.
