פקודות בסיסיות, Slash Commands ופקודות /

זהו פרק העזר המרכזי של המדריך לכל הפקודות ב-Claude Code: מתי משתמשים ב-Slash Command ומתי כותבים Prompt חופשי, טבלת עזר מלאה של כל הפקודות שאומתו מול התיעוד הרשמי בתאריך 28.07.2026, פירוט מעמיק של 12 הפקודות החשובות ביותר, פקודות ודגלים של ה-CLI, קיצורי מקלדת, השוואות בין פקודות דומות, תרגיל מסכם ופתרון תקלות.

מתי Slash Command ומתי Prompt חופשי

ב-Claude Code יש שתי דרכים עיקריות לומר למערכת מה לעשות. הדרך הראשונה היא Prompt חופשי בשפה טבעית: אתם מתארים משימה, ו-Claude מתכנן ומבצע אותה בעזרת הכלים שלו. הדרך השנייה היא פקודה שמתחילה בתו /, שנקראת Slash Command. פקודה כזאת שולטת ב-Claude Code עצמו: החלפת מודל, ניהול הרשאות, פינוי Context, הפעלת Workflow ועוד.

כלל האצבע פשוט: כשאתם רוצים שהמודל יחשוב ויעבוד על הקוד שלכם, כתבו Prompt חופשי. כשאתם רוצים לשלוט בסביבת העבודה, בהגדרות או במצב ה-Session, השתמשו בפקודה. לדוגמה: "תקן את באג ההתחברות בפרויקט TaskFlow" הוא Prompt. לעומת זאת, /model sonnet היא פקודה שמחליפה מודל, בלי לבקש מהמודל דבר.

הערה

פקודה מזוהה רק בתחילת ההודעה. טקסט שמופיע אחרי שם הפקודה הופך לארגומנטים שלה. אם שולחים פקודה בזמן ש-Claude עונה, היא נכנסת לתור ורצה אחרי סיום התור הנוכחי, מלבד פקודות כמו /status, /tasks ו-/usage שרצות מיד בלי להפריע לתשובה. החל מגרסה v2.1.199 אפשר לשרשר עד שישה Skills בתחילת הודעה אחת, למשל /skill-a /skill-b do XYZ.

תשעה סוגים שחשוב להבדיל ביניהם

המילה "פקודה" משמשת בתיעוד לכמה דברים שונים. הטבלה הבאה היא טבלת ההבחנות המחייבת של המדריך. חשוב במיוחד להבין את היחס בין Skills לפקודות מותאמות אישית: לפי התיעוד הרשמי, פקודות מותאמות אישית (Custom Commands) מוזגו לתוך מנגנון ה-Skills. קובץ בנתיב .claude/commands/deploy.md ו-Skill בנתיב .claude/skills/deploy/SKILL.md יוצרים שניהם את הפקודה /deploy ועובדים באותו אופן. קובצי .claude/commands/ קיימים ממשיכים לעבוד, אך התיעוד ממליץ על Skills כי הם תומכים בקובצי עזר, ב-Frontmatter ובטעינה אוטומטית. כאשר Skill ופקודה ותיקה חולקים שם, ה-Skill גובר.

Best Practice

לפני שמחפשים פקודה, הקלידו / בשורת הקלט: ייפתח תפריט של כל הפקודות הזמינות לכם, כולל Skills של הפרויקט ופקודות של Plugins. הקלדת אותיות אחרי ה-/ מסננת את הרשימה. זה תמיד המקור המדויק ביותר למה שזמין בסביבה הספציפית שלכם.

טבלת עזר מלאה: כל הפקודות המאומתות

הטבלאות הבאות כוללות את כל הפקודות שמופיעות בטבלת הפקודות הרשמית של Claude Code נכון ל-28.07.2026: 87 פקודות מובנות, 13 Bundled Skills ו-Workflow אחד. פקודות שלא אומתו מול התיעוד החי לא נכללות. סימון הארגומנטים כמו בתיעוד: <arg> חובה, [arg] רשות.

אזהרה

לא כל פקודה מופיעה אצל כל משתמש. הזמינות תלויה בפלטפורמה, בתוכנית (Plan) ובסביבה. לדוגמה, /desktop מוצגת רק ב-macOS וב-Windows עם מנוי Claude, ו-/upgrade לא מוצגת בתוכניות Enterprise. אילוצי גרסה מסומנים בעמודת הזמינות.

תרגיל: ניהול Session בפקודות בלבד

תרגיל 4.1: שליטה מלאה בלי Prompt חופשי אחד

המטרה: לנהל Session שלם, מודל, Context והרשאות, באמצעות פקודות וקיצורים בלבד. בצעו בסדר הבא ותעדו מה קרה בכל שלב:

  1. פתחו Session חדש בתיקיית פרויקט עם claude --permission-mode plan -n ch4-exercise.
  2. בדקו את מצב ההתקנה והחשבון עם /status, ואת ניצול ה-Context ההתחלתי עם /context.
  3. העלו את רמת המאמץ עם /effort high, ובדקו איזה מודל פעיל עם /model (צאו מהבורר בלי לשנות, עם Esc).
  4. עברו בין מצבי ההרשאות עם Shift+Tab עד שתחזרו ל-plan. שימו לב לתווית המצב מתחת לשורת הקלט.
  5. בקשו מ-Claude משימה קטנה (זה ה-Prompt היחיד המותר), למשל סקירה קצרה של מבנה הפרויקט, ואז בדקו שוב /context והשוו לניצול ההתחלתי.
  6. דחסו עם /compact keep the project structure summary ובדקו את ההשפעה עם /context.
  7. תנו שם לשיחה עם /rename ch4-done, פתחו שיחה חדשה עם /clear, וחזרו אל הישנה עם /resume ch4-done.
  8. סיימו: בדקו עלות עם /usage וצאו עם /exit.
פתרון מוסבר

שלב 1: הדגל --permission-mode plan פותח את ה-Session ישירות ב-Plan Mode, כלומר Claude יחקור אך לא יערוך קבצים; -n נותן שם שיקל על /resume בעתיד.

שלבים 2 עד 3: /status מציגה גרסה, מודל, חשבון וקישוריות. /context ההתחלתי מראה כמה מהחלון תפוס עוד לפני שכתבתם דבר: System Prompt, כלים, CLAUDE.md ושרתי MCP. /effort high נכנס לתוקף מיד. בבורר של /model שימו לב שאפשר לכוונן Effort עם החצים ושהאות s מחליפה ל-Session בלבד.

שלב 4: Shift+Tab עובר בין default (מוצג Manual), acceptEdits, plan וכל מצב נוסף שהופעל אצלכם. זה שינוי מצב לכל ה-Session, לא אישור חד-פעמי.

שלבים 5 עד 6: אחרי משימת הסקירה, /context יראה שהשיחה גדלה. הדחיסה עם הנחיית מיקוד שומרת בדיוק את מה שביקשתם. השוואת שתי התצוגות היא ההרגל החשוב ביותר לעבודה ארוכה ויעילה.

שלבים 7 עד 8: /rename ואז /clear מדגימים שהשיחה הישנה לא נמחקת אלא נשמרת בבורר; /resume ch4-done מחזיר אתכם אליה עם מלוא ההקשר. /usage מסכם את העלות, ו-/exit סוגר. אם תרצו להמשיך מחר: claude -r ch4-done מה-Terminal.
