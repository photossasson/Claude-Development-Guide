MCP מעשי מקצה לקצה

MCP (Model Context Protocol) הוא הפרוטוקול הפתוח שמחבר את Claude Code לעולם שמחוץ לתיקיית הפרויקט: מסדי נתונים, מערכות ניהול משימות, ניטור Production, תיעוד ועוד מאות שירותים. בפרק הזה נבין את הפרוטוקול מהיסוד, נעבור על כל פעולות התפעול היומיומיות עם תחביר מדויק, נבנה חמש קונפיגורציות אמיתיות (כולן בחבילת המדריך בתיקייה mcp/), נכתוב שרת MCP מינימלי משלנו, ונשווה את MCP לכל מנגנוני ההרחבה האחרים שפגשנו בחלק הזה.

לומדה אינטראקטיבית

לפרק יש לומדה משלימה: MCP ב-Claude Code, עם שרת Python שנבדק מקצה לקצה ב-Claude Code 2.1.301 ו-mcp 2.3.0, בונה פקודות claude mcp add, בודק כללי הרשאה ובודק שמות כלים (16.10.2026).

23.1 יסודות: מהו MCP ואיך הוא בנוי

הפרוטוקול, השרת והלקוח

MCP הוא תקן פתוח לחיבור בין אפליקציות AI לכלים ומקורות מידע. במקום שכל כלי AI ימציא אינטגרציה משלו לכל שירות, MCP מגדיר שפה משותפת: שרת MCP (Server) עוטף שירות כלשהו, למשל GitHub או מסד נתונים, וחושף אותו בממשק אחיד; לקוח MCP (Client) הוא האפליקציה שמתחברת לשרתים כאלה. Claude Code הוא לקוח MCP, וכפי שנראה בסוף הפרק, הוא יודע לשמש גם שרת. כך נוצרת אקוסיסטמה: כל שרת שנכתב פעם אחת עובד עם כל לקוח תואם, ולהפך.

הבעיה שהפרוטוקול פותר מוכרת לכל מי שמצא את עצמו מעתיק ידנית הודעת שגיאה מ-Sentry לצ'אט, או מדביק תיאור משימה מ-Jira: המידע קיים במערכת אחרת, ו-Claude לא רואה אותו. עם שרת MCP מחובר, Claude ניגש למערכת בעצמו, שולף את מה שצריך, ובמקרים שתאשרו גם מבצע פעולות.

שלושת ה-Primitives: Tools, Resources, Prompts

שרת MCP יכול לחשוף שלושה סוגי יכולות, וכל אחד מהם מופיע ב-Claude Code בצורה אחרת:

Primitiveמה זהאיך זה מופיע ב-Claude Code
Toolsפעולות ש-Claude יכול להפעיל (שאילתה, יצירת Issue, חיפוש)mcp__<server>__<tool>
Resourcesפריטי תוכן שהשרת חושף (מסמך, סכימה, Issue)@server:protocol://path
Promptsתבניות Prompt מוכנות שהשרת מספק/mcp__server__prompt

כלומר: כלים נקראים על ידי Claude בתוך הלולאה האגנטית (בכפוף להרשאות), Resources מוזכרים על ידכם עם @ בתוך ה-Prompt ונשלפים כקבצים מצורפים, ו-Prompts הופכים לפקודות בתפריט ה-/, כולל ארגומנטים: /mcp__github__pr_review 456. שמות שרתים ו-Prompts מנורמלים, ורווחים הופכים לקו תחתון.

Transports: איך עוברות ההודעות

  • stdio Stable: Claude Code מריץ את השרת כתהליך מקומי ומדבר איתו דרך קלט/פלט סטנדרטיים. ברירת המחדל לשרתים מקומיים, ומתאים לכל מה שצריך גישה למכונה שלכם (מסד נתונים מקומי, קבצים, דפדפן).
  • http Stable: שרת מרוחק בכתובת URL. ה-Transport המומלץ לשירותי ענן, והיחיד שתומך ב-OAuth. בקבצי JSON אפשר לכתוב גם "streamable-http" (שם ה-Transport ב-Spec) והוא יתקבל כ-Alias.
  • sse Deprecated: Server-Sent Events. מיושן רשמית; השתמשו בו רק כשהספק עדיין לא מציע נקודת קצה HTTP.
  • ws (WebSocket): חיבור דו-כיווני מתמשך לשרתים שדוחפים אירועים. מוגדר רק דרך .mcp.json או claude mcp add-json (אין --transport ws), ואימות בו הוא בכותרות בלבד, ללא OAuth.
שגיאת תצורה נפוצה

רשומת JSON עם url אבל בלי type נקראת כשרת stdio ונפסלת עם הודעת שגיאה מפורשת. תמיד ציינו "type" ברשומות של שרתים מרוחקים.

שלושת ה-Scopes וסדר העדיפויות

כל שרת מוגדר באחד משלושה Scopes, שקובעים איפה ההגדרה נשמרת ומי רואה אותה:

Scopeנטען במשותף לצוותנשמר ב
local (ברירת מחדל)הפרויקט הנוכחי בלבדלא~/.claude.json
projectהפרויקט הנוכחי בלבדכן, דרך Git.mcp.json
userכל הפרויקטים שלכםלא~/.claude.json

כשאותו שם שרת מוגדר בכמה מקומות, Claude Code מתחבר פעם אחת לפי סדר עדיפויות: local, אחר כך project, אחר כך user, אחריהם שרתים מ-Plugins, ולבסוף Connectors מ-claude.ai. הרשומה המנצחת נלקחת בשלמותה; אין מיזוג שדות. שימו לב להבחנה: "local scope" של MCP נשמר ב-~/.claude.json בתיקיית הבית, בעוד שהגדרות local כלליות יושבות ב-.claude/settings.local.json בפרויקט (פרק 17).

קובץ .mcp.json ואישור פרויקט: הקובץ יושב בשורש הפרויקט, נכנס ל-Git, ומקנה לכל הצוות אותם שרתים. מטעמי אבטחה, בפעם הראשונה ש-Claude Code פוגש שרת ברמת פרויקט הוא מבקש את אישורכם, כדי ש-Repository שקיבלתם מבחוץ לא יוכל להריץ תהליכים על המכונה בלי הסכמה. איפוס הבחירות: claude mcp reset-project-choices. אפשר לנהל את האישורים גם בהגדרות: enableAllProjectMcpServers, enabledMcpjsonServers ו-disabledMcpjsonServers; מאז גרסה 2.1.196, אישורים שמגיעים מקבצי הגדרות שנמצאים בתוך ה-Repository נכנסים לתוקף רק אחרי שאישרתם את Trust התיקייה, כך ש-Repo משובט לא יכול לאשר את השרתים של עצמו.

אימות: משתני סביבה, כותרות ו-OAuth

שלוש דרכים עיקריות, מהפשוטה למתוחכמת:

  1. משתני סביבה והרחבת ${VAR}: בקבצי התצורה אפשר לכתוב ${VAR} או ${VAR:-default} בשדות command, args, env, url ו-headers. הסוד נשאר בסביבה שלכם, והקובץ המשותף מכיל רק הפניה. משתנה שלא הוגדר ואין לו ברירת מחדל גורר אזהרה ב-claude mcp list והטקסט נשאר כפי שהוא.
  2. כותרות סטטיות: --header "Authorization: Bearer <token>" בהוספה, או שדה headers בקובץ. לסכימות מיוחדות (Kerberos, SSO פנימי) יש headersHelper: פקודת Shell שמחזירה JSON של כותרות בזמן ההתחברות.
  3. OAuth 2.0: לשרתי HTTP מתארחים. מוסיפים את השרת בלי סודות, והשרת מסומן Needs authentication; ההתחברות בדפדפן דרך /mcp או claude mcp login <name>. ה-Tokens נשמרים באחסון מאובטח ומתרעננים אוטומטית. שרתים בלי Dynamic Client Registration נתמכים עם --client-id, --client-secret ו---callback-port, ואפשר להצמיד Scopes מבוקשים עם oauth.scopes.

MCP מנוהל בארגון

מנהלי מערכת יכולים לשלוט ב-MCP ברמת הארגון (מתועד בעמוד Managed MCP הרשמי): קובץ managed-mcp.json בנתיב מערכת (ב-macOS: /Library/Application Support/ClaudeCode/, ב-Linux ו-WSL: /etc/claude-code/, ב-Windows: C:\Program Files\ClaudeCode\) פורס סט שרתים קבוע ובלעדי; מפה ריקה ({"mcpServers": {}}) מכבה MCP לגמרי. לחלופין, allowedMcpServers ו-deniedMcpServers מסננים שרתים לפי serverUrl (עם Wildcards), serverCommand (התאמה מדויקת של הפקודה) או serverName. חשוב: התאמת שם בלבד אינה בקרת אבטחה, כי כל משתמש יכול לקרוא לכל שרת בכל שם; אכיפה אמיתית נעשית לפי URL או פקודה. רשימת החסימה תמיד גוברת ומתמזגת מכל המקורות.

מודל האמון ומצבי כשל

חיבור שרת MCP הוא מתן אמון כפול: אתם סומכים על קוד השרת (בשרת stdio: קוד שרץ על המכונה שלכם) ועל התוכן שהוא מחזיר, שנכנס ישירות ל-Context של המודל. Anthropic בודקת Connectors שנכנסים ל-Directory הרשמי לפי קריטריונים, אבל אינה מבצעת Audit אבטחה לשרתי MCP. התיעוד הרשמי מזהיר במפורש: שרתים שמושכים תוכן חיצוני חושפים אתכם לסיכון Prompt Injection. ההגנות בהתאמה: הרשאות מינימליות בצד השירות, כללי הרשאות בצד Claude Code, ואישור אנושי לפעולות כתיבה (הרחבה בפרק 20, Security).

מצבי הכשל שתפגשו, לפי הסטטוסים של claude mcp list: שרת שלא מגיב (Failed to connect או Connection error), שרת שמחובר אך דורש התחברות (Needs authentication), שרת שהתחבר אך לא הצליח למסור את רשימת הכלים (Connected · tools fetch failed), ושרת פרויקט שממתין לאישורכם (Pending approval). שרתי HTTP ו-SSE שנופלים באמצע Session מתחברים מחדש אוטומטית עם Backoff מעריכי (עד חמישה ניסיונות); שרתי stdio הם תהליכים מקומיים ולא מחוברים מחדש אוטומטית.

23.2 הוראות תפעוליות: 18 פעולות שחייבים לשלוט בהן

כל הפקודות בסעיף זה רצות בטרמינל הרגיל (לא בתוך Session), אלא אם צוין שמדובר בפקודת / פנימית. כולן אומתו מול התיעוד הרשמי בתאריך המחקר.

1. הצגת השרתים המחוברים

$ claude mcp list sentry: https://mcp.sentry.dev/mcp (HTTP) - ✔ Connected

מהטרמינל: claude mcp list מציג כל שרת עם סטטוס. בתוך Session: /mcp פותח פאנל ניהול עם מספר הכלים של כל שרת, מצב אימות ופעולות (התחברות, ניתוק, הפעלה וכיבוי). קונסולות Windows ישנות מציגות √ ו-× במקום סימני היוניקוד.

2. הוספת שרת: כל Transport, כל Scope

Bash / PowerShell
# שרת HTTP מרוחק (מומלץ), scope ברירת מחדל: local
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

# שרת SSE (מיושן, רק כשאין HTTP)
claude mcp add --transport sse asana https://mcp.asana.com/sse

# שרת stdio מקומי: הפקודה אחרי המפריד --
claude mcp add playwright -- npx -y @playwright/mcp@latest

# בחירת scope: project כותב ל-.mcp.json המשותף, user לכל הפרויקטים שלכם
claude mcp add --scope project --transport http docs https://code.claude.com/docs/mcp
claude mcp add --scope user --transport http docs https://code.claude.com/docs/mcp

# מ-JSON מוכן (וגם הדרך היחידה ל-WebSocket)
claude mcp add-json weather '{"type":"http","url":"https://api.example.com/mcp"}'

# ייבוא הגדרות מאפליקציית Claude Desktop (macOS ו-WSL בלבד)
claude mcp add-from-claude-desktop

נקודות קריטיות: בשרתי stdio המפריד -- חוצץ בין הדגלים של Claude Code לפקודת השרת; בלעדיו דגלי השרת ייקראו כדגלים של Claude Code. שמות שרתים מוגבלים לאותיות, ספרות, מקף וקו תחתון, וכמה שמות שמורים (workspace ועוד) נדחים. הפקודה שומרת את התצורה בלי לאמת אותה מול השרת: Added אומר "נשמר", לא "עובד"; בדקו עם claude mcp list.

3. הסרה והשבתה

Bash / PowerShell
claude mcp remove sentry
# אם השם קיים בכמה scopes, בחרו איזה עותק להסיר:
claude mcp remove sentry --scope local

השבתה בלי מחיקה: בפאנל /mcp אפשר לכבות שרת (Toggle). הבחירה נשמרת פר פרויקט ב-~/.claude.json ברשימת disabledMcpServers, וההגדרה עצמה נשארת. זה שימושי לשרת כבד שרוצים רק בחלק מהעבודה.

4. תצורת שרת מקומי (stdio) בקובץ

.mcp.json
{
  "mcpServers": {
    "project-docs": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "${CLAUDE_PROJECT_DIR:-.}/docs"],
      "env": {}
    }
  }
}

command הוא קובץ ההפעלה, args רשימת ארגומנטים, env משתני סביבה שיוזרקו לתהליך. Claude Code מגדיר לתהליך השרת את CLAUDE_PROJECT_DIR (שורש הפרויקט), אבל מכיוון שהמשתנה קיים בסביבת השרת ולא בסביבת ההרחבה של הקובץ, שימוש בו בתוך args דורש ברירת מחדל: ${CLAUDE_PROJECT_DIR:-.}.

5. תצורת שרת מרוחק בקובץ

.mcp.json
{
  "mcpServers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer ${GITHUB_MCP_PAT}" }
    }
  }
}

שדות אופציונליים נוספים לשרת מרוחק: timeout (מילישניות, תקרה לקריאת כלי בשרת הזה), alwaysLoad (טעינת כל הכלים מראש, ראו סעיף Cost), oauth (ראו פעולה 7) ו-headersHelper.

6. העברת סודות בטוחה דרך משתני סביבה

הכלל: סודות לעולם לא נכתבים בקבצים שנכנסים ל-Git. שלוש טכניקות מדורגות:

  1. בקובץ משותף: "Authorization": "Bearer ${MY_TOKEN}", והסוד יושב רק בסביבת המשתמש של כל חבר צוות.
  2. בשרת stdio: העבירו את הסוד דרך המפתח env ("env": {"DSN": "${MY_RO_DSN}"}) ולא בתוך args; ארגומנטים של תהליך גלויים ברשימת התהליכים של המערכת.
  3. ברירות מחדל לא רגישות בלבד: ${API_BASE_URL:-https://api.example.com} בסדר; ברירת מחדל שהיא סוד, לעולם לא.

7. תהליך אימות OAuth מלא

$ claude mcp add --transport http sentry https://mcp.sentry.dev/mcp $ claude mcp login sentry Opening browser for authentication...

לחלופין, בתוך Session: /mcp, בחירת השרת, Authenticate. סיום גישה: claude mcp logout sentry, או "Clear authentication" בפאנל. במכונה בלי דפדפן (SSH): claude mcp login sentry --no-browser מדפיס כתובת; פותחים אותה מקומית ומדביקים חזרה את כתובת ה-Redirect. שרת שדורש רישום אפליקציה מראש (בלי Dynamic Client Registration): claude mcp add --transport http --client-id YOUR_ID --client-secret --callback-port 8080 my-server https://mcp.example.com/mcp; הסוד מוקלד בקלט מוסתר ונשמר במחזיק המפתחות של המערכת.

8. גילוי Tools, Resources ו-Prompts

  • Tools: /mcp, בחירת שרת, ותופיע רשימת הכלים המלאה עם שמותיהם הקנוניים. Claude מגלה אותם לבד לפי הצורך (ראו Tool Search בסעיף Cost).
  • Resources: הקלידו @ ב-Prompt; משאבי MCP מופיעים בהשלמה לצד קבצים, בפורמט @server:protocol://resource/path, עם חיפוש מטושטש (Fuzzy).
  • Prompts: הקלידו /; פקודות מ-MCP מופיעות בשם /mcp__servername__promptname ומקבלות ארגומנטים מופרדים ברווחים.

9. הגבלת כלים עם כללי הרשאות

.claude/settings.json
{
  "permissions": {
    "allow": ["mcp__github__get_*", "mcp__github__list_*"],
    "ask": ["mcp__github"],
    "deny": ["mcp__project-docs__write_file"]
  }
}

התחביר: mcp__<server> תופס את כל כלי השרת, mcp__<server>__<tool> כלי בודד, ו-mcp__<server>__* שקול לצורת השרת. בכללי allow, תווי Glob מותרים רק אחרי קידומת מפורשת mcp__<server>__ (למשל mcp__github__get_*); כלל allow לא מעוגן כמו mcp__* מדולג עם אזהרה. בכללי deny מותר גם mcp__* גורף. סדר ההכרעה תמיד: deny גובר על ask שגובר על allow (פרק 18). כלי של שרת מ-Plugin נקרא mcp__plugin_<plugin>_<server>__<tool>.

10. בחינת קריאת כלי לפני אישור

כשמופיע חלון אישור לקריאת כלי MCP, אל תאשרו אוטומטית. בדקו: (א) שם השרת והכלי בכותרת החלון, האם זה השרת שציפיתם לו; (ב) הפרמטרים המלאים המוצגים, למשל ה-SQL המדויק או תוכן ה-Issue שעומד להיכתב; (ג) האם הבקשה נובעת מההוראה שלכם או מתוכן חיצוני שהמודל קרא (סימן אזהרה קלאסי ל-Prompt Injection). ה-Transcript (Ctrl+O) מציג את קריאות הכלים המלאות גם בדיעבד. שרת יכול לסמן כלי רגיש ב-_meta עם anthropic/requiresUserInteraction, ואז החלון מופיע בכל קריאה, בלי אפשרות "אל תשאל שוב", גם במצבי הרשאות מתירניים.

11. אבחון כשלי חיבור

סדר עבודה מומלץ כשהשרת לא מתחבר:

  1. claude mcp list או /mcp לזיהוי הסטטוס המדויק.
  2. claude mcp get <name> להצגת ההגדרה בפועל, כולל מאיזה Scope היא נטענה ופירוט שגיאה.
  3. לשרת מרוחק: curl -I <url> (ב-PowerShell: curl.exe). תשובת 404 או 405 פירושה שהשרת חי (הרבה נקודות קצה של MCP עונות רק ל-POST); 401 או 403 פירושו שצריך אימות; שום תשובה: בעיית רשת או כתובת.
  4. לשרת stdio: הריצו את הפקודה המוגדרת ישירות בטרמינל. אם היא נתקעת בהמתנה לקלט, השרת תקין והבעיה בהגדרה (לרוב -- חסר); אם היא נכשלת, ההודעה תגיד מה חסר (Node, חבילה, משתנה).
  5. מידע עומק: הפעילו את Claude Code עם claude --debug, או השתמשו בפקודת /debug בתוך Session להפעלת רישום מפורט ואבחון מהלוג.

גורמים נפוצים: הוספתם את השרת בפרויקט אחר (scope local קשור לפרויקט שבו רץ add); עריכת קובץ בנתיב שגוי (הקבצים הנכונים הם ~/.claude.json ו-.mcp.json בשורש הפרויקט בלבד); JSON לא תקין (הפאנל /mcp מציג אזהרת Parse על רשומות פגומות); שרת פרויקט שדחיתם בעבר (claude mcp reset-project-choices).

12. לוגים ובריאות שוטפת

שגרת הבריאות היומיומית היא שילוב של: /mcp (סטטוס ומספרי כלים; הפאנל גם מסמן שרת שמכריז על יכולת Tools אבל לא חושף אף כלי), הודעת הפתיחה של Session שמציינת שרתים שדורשים אימות, ו-claude mcp list בסקריפטים. שרת מרוחק שמתנתק באמצע Session מסומן Pending בזמן שהחיבור מחודש אוטומטית, ואחרי חמישה כישלונות מסומן Failed עם אפשרות Retry ידני מהפאנל. שינויים ב-.mcp.json נקראים רק בהפעלת Session חדש.

13. טיפול ב-Timeouts, אי-התאמות סכימה וכשלי אימות

  • Timeout באתחול: ברירת המחדל היא 30 שניות. הרצה ראשונה של שרת npx יכולה לחרוג בגלל הורדת החבילה: MCP_TIMEOUT=60000 claude (ב-PowerShell: $env:MCP_TIMEOUT = "60000"; claude).
  • Timeout בקריאת כלי: שדה timeout פר שרת (מילישניות) גובר על משתנה הסביבה MCP_TOOL_TIMEOUT. קריאה שלא מחזירה כלום ולא שולחת Progress נעצרת גם לפי Timeout חוסר פעילות (חמש דקות לשרת מרוחק, שלושים לשרת stdio; CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT לשינוי). קריאה בשיחה הראשית שרצה מעל שתי דקות עוברת אוטומטית למשימת רקע ולא חוסמת אתכם (v2.1.212 ומעלה).
  • אי-התאמת סכימה: שרת שמצהיר על סכימת קלט עם anyOf/oneOf/allOf ברמת השורש מטופל אוטומטית מגרסה 2.1.195 (הסכימה משוטחת); במקרים שאי אפשר לשטח, הכלי הבודד מדולג והסיבה נרשמת בלוג השרת, בלי להפיל את שאר הכלים.
  • כשל אימות: תשובת 401 לשרת OAuth מחובר גוררת רענון Token וניסיון חוזר אחד אוטומטית; רק אם גם הוא נכשל השרת מסומן לחיבור מחדש, עם הפניה ל-/mcp ופעולת Re-authenticate.

14. מניעת חשיפת סודות

  • סודות רק דרך ${VAR}; אף פעם לא כתובים ב-.mcp.json או ב-managed-mcp.json (שקריא לכל משתמשי המכונה).
  • העדיפו OAuth על פני Tokens סטטיים; הוא משאיר את הקובץ נקי לגמרי.
  • זכרו ש-claude mcp add --header שומר את הערך המורחב ב-~/.claude.json; לקבצים משותפים השתמשו בהרחבת משתנים.
  • שלבו עם כללי deny על קבצי סודות (Read(.env) וכדומה, פרק 18) ועם ה-Hook לסריקת סודות מפרק 22.

15. מניעת גישה בלתי מבוקרת ל-Production

שלוש שכבות, מהחוץ פנימה: (1) בצד השירות: Credentials לקריאה בלבד (תפקיד SELECT במסד, PAT עם הרשאות Read), ורצוי מול Replica ולא מול Production עצמו; (2) בצד Claude Code: כללי deny לכלים מסוכנים וכלל ask גורף על השרת, כך שכל קריאה מוצגת לאישור; (3) בצד הארגון: allowlist מנוהל לפי URL או פקודה, כך שמשתמשים לא יכולים לחבר שרת Production לא מאושר בכלל. אל תסמכו על שכבה אחת: כלל deny מגן גם כשה-Token רחב מדי, ו-Token צר מגן גם כשמישהו שכח את הכלל.

16. שימוש בשרת קריאה בלבד

העיקרון: כשהמטרה היא לקרוא מידע (ניתוח נתונים, חקירת תקלות, סקירה), בחרו מראש תצורה שאינה מסוגלת לכתוב. הדוגמה המלאה בסעיף 23.3: DBHub עם readonly = true ברמת הכלי, מעל תפקיד מסד נתונים עם SELECT בלבד. אותו עיקרון חל על כל שירות: ב-GitHub זה PAT עם הרשאות Read בלבד, בשרת קבצים זו הגבלת התיקיות המורשות בתוספת deny על כלי הכתיבה שלו.

17. בניית שרת MCP מינימלי משלכם

ה-SDK הרשמי של Python (חבילת mcp, גרסה 2.0.0 בזמן המחקר, Python 3.10 ומעלה) הופך כל פונקציה עם Type Hints לכלי. הקוד הבא נבדק בפועל בזמן כתיבת הפרק: השרת עולה, הכלי מתגלה ומחזיר תשובה.

server.py
from mcp.server import MCPServer

mcp = MCPServer("taskflow-docs")


@mcp.tool()
def search_docs(query: str) -> str:
    """Search the TaskFlow documentation for a query string."""
    return f"Results for: {query}"


@mcp.resource("docs://readme")
def readme() -> str:
    """The project README."""
    return "TaskFlow documentation index"


if __name__ == "__main__":
    mcp.run()
$ pip install "mcp[cli]" $ claude mcp add my-docs -- python /full/path/to/server.py $ claude mcp list my-docs: python /full/path/to/server.py - ✔ Connected

שימו לב שלא כתבתם JSON Schema, ולא קוד פרוטוקול: ה-Type Hints (query: str) הם הסכימה, וה-Docstring הוא תיאור הכלי שהמודל רואה. התוספת [cli] מוסיפה את כלי הפיתוח mcp dev server.py (בדיקה ב-Inspector). הערת גרסה חשובה: זהו התחביר של גרסה 2 של ה-SDK; בגרסאות 1.x המחלקה נקראה אחרת (FastMCP), וקוד ישן ברשת עדיין מציג אותה. עדכון 16.10.2026: בגרסה 2 של ה-SDK (נבדק עם 2.3.0), חריגה רגילה בתוך כלי נחשבת קריסה, והמודל מקבל רק Error executing tool <name>. כדי שהמודל יראה את סיבת הכשל, זרקו ToolError מ-mcp.server.mcpserver.exceptions. דוגמה מלאה עם שני כלים, משאב ו-Prompt נמצאת בלומדה על MCP. מה שלא נבדק כאן: פריסה של שרת כזה כ-HTTP מרוחק עם אימות דורשת שרת אמיתי וחשבון, ולכן נשארת מחוץ לתחום הפרק; ל-Scaffolding מלא קיים גם ה-Plugin הרשמי mcp-server-dev (פרק 26).

18. ניהול גרסאות של תצורות MCP ב-Git

  • .mcp.json שייך ל-Git: הוא כל הרעיון של scope project. עברו עליו ב-Code Review כמו על כל שינוי תשתית: שרת חדש = משטח תקיפה חדש.
  • הצמידו גרסאות של שרתי stdio (@bytebase/dbhub@1.0.0 ולא @latest) כדי שכל הצוות יריץ אותו קוד וכדי שעדכון זדוני של חבילה לא ייכנס לבד. עדכנו גרסה במכוון, דרך PR.
  • אל תכניסו ל-Git: ~/.claude.json (מכיל מצב אישי וייתכנו בו Tokens), וכל קובץ סביבה עם סודות.
  • תיעדו בתוך ה-Repo (למשל README ליד הקובץ, כמו בחבילת המדריך) אילו משתני סביבה נדרשים ואיך משיגים אותם; חבר צוות חדש צריך להצליח להתחבר בלי לשאול.

23.3 דוגמאות מעשיות: חמש תצורות מוכנות

חמש התצורות הבאות נמצאות בחבילת המדריך בתיקייה mcp/, כל אחת עם .mcp.json תקין (נבדק ב-Parser) ו-README מפורט בעברית. כאן נציג כל אחת עם הקובץ המלא והנקודות החשובות; ההסברים המלאים שדה-שדה נמצאים ב-READMEs.

דוגמה 1: GitHub (שרת רשמי מרוחק, Token בכותרת)

mcp/github/.mcp.json
{
  "mcpServers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": {
        "Authorization": "Bearer ${GITHUB_MCP_PAT}"
      }
    }
  }
}

שדות: type: "http" כי זה שרת מתארח; url היא הכתובת הרשמית המתועדת; headers נושא את ה-Personal Access Token דרך משתנה הסביבה GITHUB_MCP_PAT, כך שהקובץ נקי מסודות. הרשאה מינימלית: צרו Fine-grained PAT המוגבל ל-Repositories ספציפיים עם הרשאות Read בלבד (Contents, Issues, Pull requests); הוסיפו Write רק אם אתם באמת רוצים ש-Claude ייצור PRs. הבדלי מערכת הפעלה: הגדרת המשתנה היא export GITHUB_MCP_PAT="YOUR_GITHUB_PAT" ב-Bash מול [Environment]::SetEnvironmentVariable("GITHUB_MCP_PAT", "YOUR_GITHUB_PAT", "User") ב-PowerShell. שימוש: "Review PR #456 and suggest improvements". זכרו: תוכן Issues ו-PRs הוא קלט לא מהימן.

דוגמה 3: מסד נתונים בקריאה בלבד (stdio, שלוש שכבות הגנה)

mcp/database-readonly/.mcp.json
{
  "mcpServers": {
    "taskflow-db": {
      "type": "stdio",
      "command": "npx",
      "args": [
        "-y",
        "@bytebase/dbhub@latest",
        "--transport", "stdio",
        "--config", "${CLAUDE_PROJECT_DIR:-.}/mcp/database-readonly/dbhub.toml"
      ],
      "env": {
        "DSN": "${TASKFLOW_DB_RO_DSN}"
      }
    }
  }
}
mcp/database-readonly/dbhub.toml
[[sources]]
id = "taskflow"
dsn = "${DSN}"

[[tools]]
name = "execute_sql"
source = "taskflow"
readonly = true

שדות: DBHub (@bytebase/dbhub) הוא השרת שהתיעוד הרשמי של Claude Code משתמש בו בדוגמת PostgreSQL, והוא תומך גם ב-MySQL, MariaDB, SQL Server ו-SQLite. מחרוזת החיבור עוברת דרך משתנה הסביבה DSN במפתח env (ולא ב-args, כדי שלא תופיע ברשימת התהליכים), וקובץ ה-TOML מגדיר את כלי execute_sql כ-readonly = true. הערת גרסה שאימתנו מול החבילה עצמה: בגרסה 1.0.0 הדגל הישן --readonly הוסר; מי שמעתיק פקודות ישנות מהרשת יקבל שגיאה עם הפניה לתחביר ה-TOML הזה. נדרש Node.js 22.5.0 ומעלה. שלוש השכבות: תפקיד מסד נתונים עם SELECT בלבד (סקריפט SQL מלא ב-README), אכיפת readonly ב-DBHub, וכלל ask ב-Claude Code. וגם אז: העדיפו Replica או Staging על פני Production; גם קריאה חושפת נתוני אמת לתוך ה-Context.

Troubleshooting

  • Failed to connect בשרת npx חדש: לרוב זו רק ההורדה הראשונה. המתינו והריצו claude mcp list שוב; אם נמשך, הריצו את פקודת השרת ידנית וקראו את השגיאה, או הגדילו את חלון האתחול: MCP_TIMEOUT=60000 claude.
  • Needs authentication שלא נעלם: השלימו claude mcp login <name>. אם הגדרתם גם headers.Authorization וגם השרת דוחה אותו, Claude Code מדווח כשל במקום לעבור ל-OAuth; הסירו את הכותרת או תקנו את ה-Token.
  • שרת מחובר אבל בלי כלים: /mcp, בחרו את השרת; רשימה ריקה מרמזת כמעט תמיד על משתנה סביבה חסר (API Key). העבירו עם --env KEY=value או במפתח env.
  • 404 בבחירת שרת ב-/mcp: כתובת שגויה. השוו לנתיב המתועד של הספק (/mcp בסוף הכתובת נפוץ אך לא אוניברסלי), הסירו והוסיפו מחדש.
  • Connector מ-claude.ai לא מופיע: Connectors נטענים רק כשההתחברות הפעילה היא מנוי claude.ai. הריצו /status לבדוק איזו שיטת אימות פעילה (משתנה ANTHROPIC_API_KEY פעיל חוסם אותם), ואז /login.
  • שרת נעלם בלי הסבר: ייתכן שמדיניות ארגונית חדשה (allowlist או denylist) חסמה אותו; החסימה שקטה. בדקו מול מנהל המערכת (עמוד Managed MCP).
  • פלט ענק שנחתך: אזהרה מעל 10,000 Tokens וחיתוך ב-25,000; הגדילו עם MAX_MCP_OUTPUT_TOKENS או בקשו שאילתות ממוקדות יותר.
  • תקלות רוחביות נוספות: פרק 39 (Troubleshooting מרוכז).

Security: קלט חיצוני הוא קלט עוין עד שהוכח אחרת

סכנה

כל תוכן שמגיע דרך שרת MCP, הודעת שגיאה מ-Sentry, תיאור Issue, תוצאת שאילתה, הוא קלט לא מהימן שנכנס ישירות ל-Context של המודל. תוקף שיכול לכתוב לאחת המערכות המחוברות יכול לנסות לשתול בהן הוראות (Prompt Injection) שירוצו בהרשאות שלכם. התיעוד הרשמי מזהיר על כך במפורש.

  • חברו רק שרתים שאתם סומכים על מקורם; העדיפו שרתים רשמיים של הספק או מה-Directory של Anthropic.
  • הרשאה מינימלית בצד השירות: Read-only כברירת מחדל, הרחבה רק לפי צורך מוכח.
  • אישור אנושי לכל פעולת כתיבה שמקורה בתוכן חיצוני; חשדו בכל בקשת כלי שלא נובעת ישירות מההוראה שלכם.
  • סודות רק דרך משתני סביבה או OAuth; לעולם לא בקבצים משותפים.
  • בארגון: אכיפת allowlist לפי URL או פקודה, לא לפי שם.
  • העמיקו בפרק 20, Security: מודל האיומים המלא, Sandboxing ושכבות ההגנה המשלימות.

Cost ו-Context: כמה עולה כל שרת מחובר

לכל שרת מחובר יש מחיר הקשרי. בעבר כל סכימות הכלים נטענו מראש; היום ברירת המחדל היא Tool Search: רק שמות הכלים והוראות השרת נטענים בתחילת ה-Session, וסכימות מלאות נשלפות על ידי Claude רק כשכלי רלוונטי למשימה (מנגנון הכלים הנדחים, Deferred Tools). המשמעות: חיבור שרתים רבים משפיע מעט יחסית על ה-Context, והמגבלה המעשית היא תקציב ה-Context שלכם ולא מכסת שרתים. שליטה: ENABLE_TOOL_SEARCH (ערכים true, false, auto, auto:N), ופטור פר שרת עם "alwaysLoad": true לכלים שנחוצים בכל תור (במחיר Context קבוע). המנגנון דורש מודלים מ-Sonnet 4.5 ו-Opus 4.5 ומעלה.

הצד השני הוא תוצאות הכלים: שאילתת מסד נתונים רחבה או חיפוש לוגים יכולים להחזיר עשרות אלפי Tokens שיישבו ב-Context עד סוף ה-Session. Claude Code מזהיר מעל 10,000 Tokens לתוצאה וחותך ב-25,000 (MAX_MCP_OUTPUT_TOKENS להגדלה). הרגלים טובים: בקשו שאילתות ממוקדות, הסירו שרתים שאינם בשימוש, ועקבו עם /context (פרק 14) כמה מה-Context הולך לכלים ולתוצאותיהם.

Best Practices

  • התחילו כל חיבור חדש עם שרת התיעוד (claude-code-docs): בלי אימות, בלי סיכון, ומלמד את כל המנגנון.
  • Scope לפי תפקיד: user לכלים אישיים חוצי פרויקטים, project לכל מה שהצוות צריך, local לניסויים.
  • OAuth כשאפשר, ${VAR} כשחייבים Token, ולעולם לא סוד בקובץ.
  • הרשאה מינימלית כברירת מחדל: Read-only קודם, והרחבה נקודתית עם כללי allow לכלי קריאה בלבד.
  • הצמידו גרסאות שרתי stdio ב-.mcp.json ועדכנו דרך PR.
  • בדקו כל שרת חדש עם claude mcp list מיד אחרי ההוספה, ואל תניחו ש-Added פירושו Connected.
  • הסירו או כבו שרתים שאינם בשימוש; בדקו אחת לתקופה עם /mcp מה באמת מחובר.

Anti-patterns

  • חיבור "כל מה שמצאתי ב-Reddit": שרת MCP הוא קוד שרץ בהרשאותיכם או שירות שמקבל את הנתונים שלכם. מקור לא מוכר = לא מחברים.
  • DSN של Production עם משתמש Admin "רק לרגע": אין דבר כזה רק לרגע. תפקיד קריאה בלבד לוקח שתי דקות להקים.
  • אישור עיוור של חלונות הרשאה: אם אתם מאשרים בלי לקרוא את הפרמטרים, ביטלתם את שכבת ההגנה החשובה ביותר.
  • allow גורף לכל כלי השרת ביום הראשון: קודם תכירו את הכלים במצב ask, אחר כך תפתחו נקודתית.
  • שימוש ב-MCP למה שכלי מובנה עושה: Claude קורא קבצים, מריץ Git ומחפש בקוד בכלים המובנים; שרת שמשכפל אותם רק מוסיף עלות ומשטח תקיפה.
  • Token אחד משותף לכל הצוות: מבטל את יכולת ה-Audit ומרחיב את נזק הדליפה. אימות פר משתמש, תמיד.

תרגיל: חיבור מקור תיעוד ושאילתה

תרגיל 23.1

חברו את שרת התיעוד הרשמי של Claude Code ובדקו אותו מקצה לקצה:

  1. הוסיפו את השרת claude-code-docs (כתובת: https://code.claude.com/docs/mcp) ב-scope local.
  2. ודאו שהוא מחובר, ובדקו כמה כלים הוא חושף.
  3. בתוך Session, בקשו מ-Claude לברר דרך השרת מה עושה משתנה הסביבה MAX_MCP_OUTPUT_TOKENS, וודאו בפלט שהתשובה אכן הגיעה מהשרת.
  4. העבירו את השרת ל-scope user, כך שיהיה זמין בכל הפרויקטים שלכם.
  5. נקו אחריכם: הסירו את השרת לגמרי וודאו שהוסר.
פתרון מוסבר

שלב 1, הוספה (מהטרמינל, בתיקיית פרויקט כלשהי):

$ claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp Added HTTP MCP server claude-code-docs with URL: https://code.claude.com/docs/mcp to local config

שלב 2, בדיקה: claude mcp list אמור להציג ✔ Connected. בתוך Session, /mcp ובחירת השרת מציגים את רשימת הכלים ומספרם.

שלב 3, שאילתה: פתחו claude וכתבו: Use the claude-code-docs server to look up what MAX_MCP_OUTPUT_TOKENS does. בקריאה הראשונה יופיע חלון אישור לכלי החדש; אשרו. בפלט תראו את קריאת הכלי מסומנת בשם השרת, וזו ההוכחה שהתשובה הגיעה מהשרת ולא מהידע הפנימי של המודל. התשובה הצפויה: המשתנה מעלה את תקרת פלט כלי ה-MCP מעל ברירת המחדל של 25,000 Tokens.

שלב 4, שינוי scope: ה-scope קבוע בעת ההוספה, ולכן הדרך היא הסרה והוספה מחדש:

$ claude mcp remove claude-code-docs --scope local $ claude mcp add --scope user --transport http claude-code-docs https://code.claude.com/docs/mcp

שלב 5, ניקוי: claude mcp remove claude-code-docs, ואימות אחרון עם claude mcp list שהשרת אינו מופיע. שימו לב מה תרגלתם בדרך: הוספה, אימות חיבור, אישור כלי ראשון, ניהול scopes והסרה, שהם בדיוק מחזור החיים המלא של כל שרת MCP שתחברו אי פעם.

אימות למידה: ודאו שאתם יודעים לענות בלי להציץ: מה ההבדל בין שלושת ה-Scopes ומי גובר על מי? למה שרת פרויקט דורש אישור בפעם הראשונה? איך כותבים כלל שמאשר רק כלי קריאה של שרת? ולמה תוצאה של שאילתת מסד נתונים היא גם שאלת אבטחה וגם שאלת Context?

סיכום

MCP הוא שער היציאה של Claude Code לעולם: פרוטוקול פתוח אחד, שלושה Primitives (כלים, משאבים, Prompts), שלושה Scopes, ותשתית אימות והרשאות מלאה. למדנו להוסיף, לאמת, לאבחן ולהסיר שרתים בכל ה-Transports; לנהל סודות נכון (משתני סביבה ו-OAuth, לעולם לא בקבצים); לבנות הגנה בשכבות מול Production (הרשאות בצד השירות, כללים בצד Claude Code, מדיניות בצד הארגון); ואפילו לכתוב שרת משלנו בחמש עשרה שורות Python. חמש התצורות בתיקיית mcp/ מוכנות להעתקה לפרויקטים שלכם. בפרק הבא נראה את הצד המנוהל של אותו מטבע: Connectors, שרתי MCP שמגיעים דרך claude.ai עם בקרות ארגוניות מובנות.
