Claude Code בתוך VS Code ו-JetBrains

עד עכשיו עבדנו עם Claude Code בעיקר בטרמינל. בפרק הזה נעביר אותו אל תוך ה-IDE: תוסף VS Code עם פאנל גרפי מלא, תוספת JetBrains שמתחברת ל-IntelliJ, PyCharm ו-WebStorm, ונבין מתי כל ממשק מנצח. נכסה התקנה, אזכורי @ עם טווחי שורות, תצוגות Diff, סקירת תוכניות, Checkpoints, קיצורי מקלדת, חיבור לדפדפן עם @browser, וטבלת השוואה מלאה בין כל המשטחים.

למה להריץ את Claude Code בתוך ה-IDE

Claude Code הוא אותו מנוע בכל מקום: אותם מודלים, אותם כלים, אותם קובצי CLAUDE.md והגדרות. מה שמשתנה בין המשטחים הוא הממשק והאינטגרציה עם סביבת העבודה. כשמריצים אותו בתוך ה-IDE מקבלים שלושה יתרונות שהטרמינל לבדו לא נותן:

  • הקשר אוטומטי מהעורך. הטקסט שסימנתם בעורך משותף עם Claude אוטומטית, כולל נתיב הקובץ ומספרי השורות. אין צורך להדביק קוד או לתאר "הפונקציה בערך באמצע הקובץ".
  • תצוגות Diff מקוריות. שינויים מוצגים במציג ה-Diff של ה-IDE, זה לצד זה, במקום כטקסט בטרמינל.
  • שיתוף Diagnostics. שגיאות Lint ו-Syntax שה-IDE מזהה זורמות ל-Claude בלי שתצטרכו להעתיק אותן.

מתי זה פחות מתאים: אוטומציה וסקריפטים (claude -p), עבודה על שרת מרוחק דרך SSH בלבד, או כשצריך פקודות שקיימות רק ב-CLI. בהמשך הפרק נראה שקל לשלב: אפשר לעבוד ב-CLI בתוך הטרמינל המשולב של ה-IDE וליהנות משני העולמות.

דרישות מוקדמות

התקנה עובדת של Claude Code CLI וחיבור לחשבון (פרק 2). נדרש מנוי בתשלום (Pro, Max, Team או Enterprise) או חשבון Claude Console; אין צורך במפתח API. היכרות עם מצבי הרשאות (פרק 18) ועם Checkpoints (פרק 19) תעזור.

VS Code: התקנה ודרישות

תוסף VS Code הוא הדרך המומלצת רשמית להשתמש ב-Claude Code בתוך VS Code: פאנל גרפי מלא, לא עוד טרמינל בתוך חלון. הדרישות:

  • VS Code בגרסה 1.94.0 ומעלה.
  • חשבון Anthropic: מנוי בתשלום או חשבון Console. מתחברים דרך הדפדפן בפתיחה הראשונה.

ההתקנה: פתחו את תצוגת ה-Extensions (Ctrl+Shift+X ב-Windows/Linux, Cmd+Shift+X ב-Mac), חפשו Claude Code ולחצו Install. התוסף עובד גם ב-Cursor ובפיצולי VS Code אחרים (כמו Kiro), כולל התקנה מ-Open VSX. אם התוסף לא מופיע אחרי ההתקנה, הריצו Developer: Reload Window מה-Command Palette.

התוסף וה-CLI הם שתי התקנות נפרדות

התוסף מגיע עם עותק פרטי של ה-CLI עבור פאנל הצ'אט בלבד, והוא לא מוסיף את claude ל-PATH. כדי להריץ claude בטרמינל המשולב צריך גם את ההתקנה העצמאית של ה-CLI מפרק 2. בכיוון ההפוך: הרצת claude בטרמינל המשולב מתקינה את התוסף אוטומטית אם הוא חסר (אפשר לכבות עם ההגדרה autoInstallIdeExtension או משתנה הסביבה CLAUDE_CODE_IDE_SKIP_AUTO_INSTALL=1).

אחרי ההתקנה, סמל ה-Spark (ניצוץ) מייצג את Claude Code בכל רחבי VS Code. ארבע דרכים לפתוח את הפאנל:

  • Editor Toolbar: סמל ה-Spark בפינת העורך (מופיע רק כשקובץ פתוח).
  • Activity Bar: סמל ה-Spark בסרגל הצד פותח את רשימת ה-Sessions.
  • Command Palette: הקלידו Claude Code ובחרו פעולה כמו Open in New Tab.
  • Status Bar: לחיצה על Claude Code בפינה התחתונה, עובד גם בלי קובץ פתוח.

בפתיחה הראשונה מופיע מסך התחברות; לחצו Sign in והשלימו את האישור בדפדפן. אחרי ההתחברות מופיעה רשימת Learn Claude Code עם סיור מודרך; אפשר גם להריץ Claude Code: Open Walkthrough מה-Command Palette בכל שלב.

לאן לעגן את הפאנל: גררו את הפאנל לכל מקום: Secondary Sidebar (צד ימין, Claude נשאר גלוי בזמן שאתם מקודדים), Primary Sidebar, או כלשונית באזור העורך. אפשר לפתוח כמה שיחות במקביל עם Open in New Tab או Open in New Window; נקודה צבעונית על סמל ה-Spark מסמנת סטטוס: כחול פירושו בקשת הרשאה ממתינה, כתום פירושו ש-Claude סיים בזמן שהלשונית הייתה מוסתרת.

VS Code: עבודה בפאנל

תיבת ה-Prompt היא מרכז השליטה. מחוון המצב בתחתית התיבה מחליף בין מצבי הרשאות בלחיצה:

  • Manual: Claude מבקש אישור לפני עריכות ורוב פקודות ה-Shell.
  • Plan: Claude מתאר מה יעשה וממתין לאישור. VS Code פותח את התוכנית אוטומטית כמסמך Markdown מלא שבו אפשר להוסיף הערות Inline כמשוב לפני שהעבודה מתחילה. זו חוויית סקירת התוכניות החזקה ביותר מבין כל המשטחים.
  • Edit automatically: עריכות מתבצעות בלי לשאול (מקביל ל-acceptEdits).

ברירת המחדל לשיחות חדשות נקבעת בהגדרה claudeCode.initialPermissionMode (ערכים: default, plan, acceptEdits, bypassPermissions). עוד בתיבה: הקלדת / פותחת את תפריט הפקודות (צירוף קבצים, החלפת מודל, Extended Thinking, /usage, ניהול MCP, Hooks, Memory ו-Plugins), מחוון ה-Context מציג כמה מחלון ההקשר מנוצל, ו-Shift+Enter יורד שורה בלי לשלוח.

אזכורי @ עם טווחי שורות

אזכור עם @ מוסיף קובץ או תיקייה להקשר, עם התאמה מקורבת (Fuzzy Matching):

Prompt
Explain the logic in @auth        (מתאים ל-auth.js, AuthService.ts וכו')
What's in @src/components/        (לוכסן בסוף עבור תיקייה)

החלק החזק באמת: בחירת טקסט בעורך משותפת עם Claude אוטומטית. כותרת תיבת ה-Prompt מציגה כמה שורות מסומנות, ולחיצה על המחוון מסתירה את הבחירה מ-Claude (סמל עין חצויה). לחיצה על Option+K ב-Mac או Alt+K ב-Windows/Linux מוסיפה אזכור מפורש עם נתיב וטווח שורות, למשל @app.ts#5-10. אפשר גם לגרור קבצים לתיבה תוך החזקת Shift כדי לצרפם, לבקש עמודים ספציפיים מ-PDF גדול, ולהפנות לפלט טרמינל עם @terminal:name (כאשר name הוא כותרת הטרמינל), בלי העתקות.

אישור שינויים עם Diff

כש-Claude רוצה לערוך קובץ, מופיעה השוואה זה לצד זה של המקור וההצעה, ואז בקשת הרשאה: לאשר, לדחות, או להגיד ל-Claude מה לעשות במקום. טריק שימושי ומתועד: אם תערכו את התוכן המוצע ישירות בתצוגת ה-Diff לפני האישור, Claude מקבל הודעה שהתוכן שונה, כך שהוא לא מניח שהקובץ תואם להצעה המקורית שלו.

Checkpoints ו-Rewind בתוסף

התוסף תומך ב-Checkpoints באופן מלא. רחפו מעל כל הודעה בשיחה כדי לחשוף את כפתור ה-Rewind, עם שלוש אפשרויות:

  • Fork conversation from here: ענף שיחה חדש מנקודה זו, שינויי הקוד נשארים.
  • Rewind code to here: החזרת הקבצים למצבם בנקודה זו, השיחה נשמרת במלואה.
  • Fork conversation and rewind code: שניהם יחד.

המגבלות זהות לאלה של ה-CLI (ראו פרק 19): Checkpoints עוקבים אחרי עריכות של Claude, לא אחרי כל שינוי בפרויקט.

היסטוריה והמשך שיחות מהענן

כפתור Session history בראש הפאנל פותח חיפוש ודפדוף בכל השיחות, עם שמות שנוצרים אוטומטית, שינוי שם ומחיקה. יש שתי לשוניות: Local ו-Web. לשונית Web מציגה Sessions מ-Claude Code on the web ומאפשרת להוריד אותם ולהמשיך מקומית; זה דורש התחברות עם מנוי Claude.ai (לא Console), מציג רק Sessions שנפתחו עם Repository של GitHub, והשינויים לא מסונכרנים חזרה לענן. התוסף וה-CLI חולקים היסטוריית שיחות: claude --resume בטרמינל פותח בוחר שבו אפשר להמשיך שיחה שהתחילה בתוסף.

הגדרות התוסף ומצב Terminal

יש שתי שכבות הגדרות: הגדרות התוסף ב-VS Code (התנהגות בתוך העורך) והגדרות Claude Code ב-~/.claude/settings.json, המשותפות לתוסף ול-CLI (הרשאות, Hooks, MCP; ראו פרק 17). ההגדרות המרכזיות של התוסף:

הגדרהברירת מחדלמה היא עושה

מצב Terminal: מי שמעדיף את ממשק ה-CLI המלא בתוך VS Code מסמן את Use Terminal בהגדרות (Extensions ואז Claude Code). כך מקבלים את כל פקודות ה-CLI, כולל קיצור ה-! ו-Tab Completion, שאינם זמינים בפאנל הגרפי.

ספקי צד שלישי: אם הארגון עובד מול Amazon Bedrock, Google Cloud's Agent Platform או Microsoft Foundry: סמנו את Disable Login Prompt בהגדרות התוסף, והגדירו את הספק ב-~/.claude/settings.json לפי מדריך הספק, כך שהתצורה משותפת לתוסף ול-CLI.

Plugins ו-MCP: הקלדת /plugins בפאנל פותחת ממשק גרפי לניהול Plugins ו-Marketplaces (עם בחירת Scope: משתמש, פרויקט או מקומי; ראו פרק 26). הוספת שרתי MCP נעשית דרך ה-CLI בטרמינל המשולב (claude mcp add), וניהול שרתים קיימים עם /mcp בפאנל.

דפדפן עם @browser: אם מותקן תוסף Claude in Chrome (גרסה 1.0.36 ומעלה), הקלידו @browser בתיבת ה-Prompt ואחריו את המשימה, למשל @browser go to localhost:3000 and check the console for errors. בניגוד ל-CLI, בתוסף VS Code אין צורך בדגל --chrome. פירוט בהמשך הפרק.

JetBrains: התקנה ותצורה

תוספת ה-JetBrains Beta עובדת עם רוב סביבות JetBrains, כולל IntelliJ IDEA, PyCharm, Android Studio, WebStorm, PhpStorm ו-GoLand. ההבדל המהותי מהתוסף של VS Code: התוספת לא מכילה עותק של ה-CLI. היא מריצה את הפקודה claude בטרמינל המשולב של ה-IDE ומתחברת אליה, ולכן חובה להתקין את שני החלקים:

  1. התקינו את Claude Code CLI (אם עוד לא; פרק 2). בלעדיו התוספת תציג הודעת Cannot launch Claude Code.
  2. התקינו את Claude Code [Beta] מה-JetBrains Marketplace והפעילו את ה-IDE מחדש (לפעמים נדרשת הפעלה מחדש מלאה, אפילו יותר מפעם אחת).

היכולות המרכזיות של האינטגרציה:

  • Quick Launch: Cmd+Esc ב-Mac או Ctrl+Esc ב-Windows/Linux פותחים את Claude Code ישירות מהעורך.
  • Diff Viewer: שינויים נפתחים במציג ה-Diff של ה-IDE במקום בטרמינל. נשלט דרך הגדרת Diff tool ב-/config (הערך auto מציג ב-IDE, terminal משאיר בטרמינל). ההגדרה מופיעה ב-/config רק כשיש חיבור פעיל ל-IDE.
  • שיתוף בחירה: הבחירה או הלשונית הנוכחית ב-IDE משותפות עם Claude אוטומטית. חוקי Deny על Read חוסמים שיתוף עבור קבצים רגישים.
  • קיצור אזכור קובץ: Cmd+Option+K ב-Mac או Alt+Ctrl+K ב-Windows/Linux מוסיפים אזכור כמו @src/auth.ts#L1-99.
  • שיתוף Diagnostics: שגיאות Lint ו-Syntax מה-IDE משותפות עם Claude תוך כדי עבודה.

הגדרות התוספת נמצאות ב-Settings ואז Tools ואז Claude Code [Beta]. השדה החשוב ביותר הוא Claude command: נתיב או פקודה מותאמים להרצת Claude, למשל /usr/local/bin/claude או npx @anthropic-ai/claude-code. למשתמשי WSL התיעוד ממליץ להגדיר שם: wsl -d Ubuntu -- bash -lic "claude" (החליפו Ubuntu בשם ההפצה שלכם). עוד בהגדרות: השתקת התראות על פקודה חסרה, הפעלת Option+Enter לשורות מרובות ב-macOS, ועדכוני תוספת אוטומטיים.

תיקון בעיית ה-ESC

בעיה ידועה ומתועדת: מקש Esc לא עוצר את Claude Code בטרמינל של JetBrains, כי ה-IDE תופס אותו כדי להחזיר מיקוד לעורך. התיקון:

  1. פתחו Settings ואז Tools ואז Terminal.
  2. בטלו את הסימון של Move focus to the editor with Escape, או לחצו Configure terminal keybindings ומחקו את הקיצור Switch focus to Editor.
  3. החילו את השינויים. מעכשיו Esc יעצור את Claude כרגיל.

Remote Development ו-WSL2

Remote Development: התוספת מותקנת על ה-Host

בעבודה עם JetBrains Remote Development חובה להתקין את התוספת על המחשב המרוחק דרך Settings ואז Plugin (Host), לא על המכונה המקומית. זו הסיבה הנפוצה ביותר לכך שהאינטגרציה "לא עובדת" בסביבות מרוחקות.

WSL2: אם Claude Code רץ בתוך WSL2 וה-IDE על Windows, ייתכן ש-/ide יציג No available IDEs detected. הגורם הרגיל: רשת ה-NAT של WSL2 או Windows Firewall חוסמים את החיבור. שני תיקונים מתועדים:

תיקון 1 (מומלץ): חוק Firewall. מצאו את הכתובת עם hostname -I בתוך WSL, גזרו את ה-Subnet (שני המקטעים הראשונים ואז .0.0/16), והריצו ב-PowerShell כמנהל:

PowerShell (Administrator)
New-NetFirewallRule -DisplayName "Allow WSL2 Internal Traffic" `
  -Direction Inbound -Protocol TCP -Action Allow `
  -RemoteAddress 172.21.0.0/16 -LocalAddress 172.21.0.0/16

התאימו את טווח הכתובות ל-Subnet שלכם, ואז הפעילו מחדש את ה-IDE ואת Claude Code.

תיקון 2: Mirrored Networking (דורש Windows 11 22H2 ומעלה). הוסיפו לקובץ .wslconfig בתיקיית המשתמש ב-Windows:

%USERPROFILE%\.wslconfig
[wsl2]
networkingMode=mirrored

ואז wsl --shutdown מ-PowerShell והפעלה מחדש. התיעוד מעדיף את המצב הזה על פני פתיחת ההאזנה לכל הרשת (ראו סעיף האבטחה).

העיקרון: הפאנל של VS Code מצטיין בסקירה ויזואלית ובעבודה יומיומית; ה-CLI מצטיין בשליטה מלאה ובאוטומציה. טבלת ההבדלים המתועדת בין ה-CLI לתוסף VS Code:

שלוש דרכים לשלב בין העולמות:

  • CLI בתוך ה-IDE: פתחו את הטרמינל המשולב (Ctrl+` או Cmd+`) והריצו claude. ה-CLI מתחבר ל-IDE אוטומטית ומקבל את תצוגות ה-Diff ושיתוף ה-Diagnostics.
  • חיבור מטרמינל חיצוני עם /ide: הפקודה /ide מנהלת את חיבורי ה-IDE ומציגה סטטוס. הריצו אותה מכל טרמינל כדי לחבר Session רץ ל-VS Code או ל-JetBrains; בהצלחה תופיע הודעה כמו Connected to IntelliJ IDEA. אם Claude Code מזהה IDE רץ בלי התוספת, /ide אף מתקין אותה עבורכם ומבקש הפעלה מחדש.
  • המשך שיחה בין ממשקים: claude --resume בטרמינל ממשיך שיחה שהתחילה בפאנל של VS Code, ולהפך; ההיסטוריה משותפת.

תהליכי רקע: כש-Claude מריץ פקודות ארוכות בפאנל של VS Code, ההתקדמות מוצגת ב-Status Bar, אבל הנראות של משימות רקע מוגבלת לעומת ה-CLI. הטיפ המתועד: בקשו מ-Claude להדפיס את הפקודה והריצו אותה בעצמכם בטרמינל המשולב כשחשוב לכם לראות פלט חי.

Git בתוך ה-IDE

עבודת ה-Git זהה לזו שלמדתם בפרקי היסוד, רק בלי לעזוב את העורך: בקשו commit my changes with a descriptive message או create a pr for this feature, ו-Claude יכין Commit או Pull Request עם תיאור המבוסס על השינויים בפועל. למשימות מקבילות, הדגל --worktree (בקיצור -w) מפעיל את Claude ב-Git Worktree מבודד עם קבצים ו-Branch משלו:

$ claude --worktree feature-auth

כך כמה מופעי Claude בטרמינלים שונים של אותו חלון VS Code לא דורכים זה על זה.

שני משטחים משלימים: Desktop ו-Chrome

שני משטחים נוספים משיקים לעבודת ה-IDE ומכוסים בהרחבה בפרקים אחרים; הנה מפת הדרכים בקצרה.

אפליקציית Desktop, לשונית Code: אפליקציית Claude Desktop (ל-macOS ו-Windows; גרסת Linux ב-Beta) כוללת לשונית Code שהיא סביבת פיתוח גרפית מלאה: Sessions מקביליים עם בידוד אוטומטי באמצעות Git Worktrees, תצוגת Diff עם הערות Inline, כפתור Review code, פאנל דפדפן לתצוגה מקדימה של האפליקציה, טרמינל משולב, ומעקב אחרי Pull Requests עם Auto-fix ו-Auto-merge. ה-Desktop וה-CLI חולקים את אותם קובצי תצורה (CLAUDE.md, settings.json, MCP). מעבר מה-CLI: הפקודה /desktop שומרת את ה-Session הנוכחי ופותחת אותו באפליקציה (זמינה ב-macOS וב-Windows x64 עם מנוי Claude; לא עם מפתח API או ספקי צד שלישי). ההשוואה המלאה בהמשך; הצלילה העמוקה בפרק על משטחי העבודה הנוספים.

אינטגרציית Chrome (@browser): תוסף Claude in Chrome מחבר את Claude Code לדפדפן שלכם: בדיקת אפליקציות Web, קריאת שגיאות Console, מילוי טפסים, חילוץ נתונים והקלטת GIF. עובד עם Chrome, Edge ודפדפני Chromium נוספים (Brave, Arc, Vivaldi, Opera); לא נתמך ב-WSL. דרישות: תוסף בגרסה 1.0.36 ומעלה, תוכנית ישירה של Anthropic (Pro, Max, Team או Enterprise) והתחברות עם /login; לא זמין עם מפתח API, עם claude setup-token, או דרך Bedrock, Agent Platform ו-Foundry. ב-CLI מפעילים עם claude --chrome ובודקים סטטוס עם /chrome; בתוסף VS Code פשוט כותבים @browser בתיבת ה-Prompt. חשוב להבין את מודל האמון: Claude פותח לשוניות חדשות ומשתף את מצב ההתחברות של הדפדפן שלכם, כלומר ניגש לאתרים שאתם מחוברים אליהם. בעמידה בפני דף התחברות או CAPTCHA הוא עוצר ומבקש מכם להמשיך ידנית.

שגיאות נפוצות

  • לצפות ש-claude יעבוד בטרמינל אחרי התקנת התוסף בלבד. התוסף של VS Code לא מוסיף את ה-CLI ל-PATH; נדרשת התקנה עצמאית.
  • ההפך ב-JetBrains: להתקין רק את התוספת. שם אין CLI מובנה כלל, ובלי התקנת CLI תופיע שגיאת Cannot launch Claude Code.
  • להפעיל את Claude מתיקייה שאינה שורש הפרויקט של ה-IDE. האינטגרציה מניחה שהתיקיות תואמות; הפעילו את claude מאותה תיקייה שה-IDE פתח.
  • לחפש את סמל ה-Spark בלי קובץ פתוח. סמל ה-Editor Toolbar מופיע רק כשקובץ פתוח; השתמשו ב-Status Bar או ב-Command Palette.
  • לשכוח שהבחירה בעורך משותפת אוטומטית. אם סימנתם קוד רגיש, הוא נשלח כהקשר. השתמשו במחוון הבחירה או בחוקי Deny (ראו אבטחה).
  • לצפות שהתקנת Plugin בתוסף תשפיע רק על VS Code. ניהול ה-Plugins בתוסף משתמש באותן פקודות CLI מתחת למכסה; ההגדרה משותפת לשני הממשקים.

Troubleshooting

התוסף לא מתחבר או שסמל ה-Spark לא מופיע: ודאו VS Code בגרסה 1.94.0 ומעלה (Help ואז About), פתחו קובץ כלשהו, הריצו Developer: Reload Window, נטרלו זמנית תוספי AI מתחרים (Cline, Continue וכדומה), וודאו שה-Workspace אינו ב-Restricted Mode: התוסף לא עובד שם. אם Claude לא מגיב לפניות, הריצו claude בטרמינל כדי לקבל הודעות שגיאה מפורטות יותר.

/ide מציג "No available IDEs detected": ודאו שהתוספת מותקנת ומופעלת, הפעילו את ה-IDE מחדש לגמרי, וודאו שהרצתם את claude מהטרמינל המשולב אם ציפיתם לחיבור אוטומטי. ב-WSL2 עברו על סעיף ה-Firewall וה-Mirrored Networking למעלה.

JetBrains Remote Development לא עובד: כמעט תמיד התוספת מותקנת בצד הלא נכון. התקינו אותה על ה-Host המרוחק (Settings ואז Plugin (Host)) והפעילו מחדש.

לחיצה על סמל Claude ב-JetBrains מציגה "command not found": ודאו עם claude --version בטרמינל שה-CLI מותקן, ואז הגדירו את הנתיב המלא בשדה Claude command בהגדרות התוספת. ב-WSL השתמשו בתבנית wsl -d <distro> -- bash -lic "claude".

ה-Diff לא נפתח ב-IDE: הריצו /config וודאו ש-Diff tool על auto. זכרו שהערך מופיע רק כשיש חיבור IDE פעיל, אז קודם /ide.

אבטחה

עריכה אוטומטית יכולה לשנות קבצים שה-IDE מריץ

במצב עריכה אוטומטית (acceptEdits), Claude יכול לשנות קובצי תצורה של העורך שה-IDE עלול להריץ אוטומטית: ב-VS Code למשל settings.json או tasks.json, וב-JetBrains קובצי תצורת IDE מקבילים. זה עלול לעקוף בפועל את בקשות האישור להרצת Bash. עם קוד לא מהימן: עבדו במצב Manual, הפעילו VS Code Restricted Mode ל-Workspaces לא מהימנים, וסקרו שינויים לפני אישור.

שיתוף בחירה וקבצים רגישים: בזמן חיבור ל-IDE, ה-CLI מוסיף לכל Prompt את הבחירה הנוכחית ואת נתיב הקובץ הפעיל (מופיע ב-Transcript כשורת Selected N lines from ...). כדי להחריג קובץ רגיש כמו .env, הוסיפו חוק Deny על Read לנתיב שלו; החוק חוסם גם את הטקסט הנבחר וגם את ציון הקובץ הפתוח.

שרת ה-MCP הפנימי של ה-IDE: שני התוספים מריצים שרת MCP מקומי בשם ide שה-CLI מתחבר אליו (הוא מוסתר מ-/mcp). האימות: Token אקראי חדש בכל הפעלה, בקובץ נעילה ב-~/.claude/ide/<port>.lock עם הרשאות מתאימות. ב-VS Code השרת חשוף למודל בשני כלים בלבד: mcp__ide__getDiagnostics (קריאה בלבד) ו-mcp__ide__executeCode (הרצת Python ב-Jupyter Notebook, תמיד עם חלון אישור מקורי ב-VS Code שאי אפשר לדלג עליו). ב-JetBrains נחשף רק mcp__ide__getDiagnostics, ואין כלי הרצת קוד.

JetBrains: אל תפתחו את ההאזנה לכל הרשת בלי צורך

ההגדרה Accept connections from all network interfaces (תחת Networking (Advanced)) חושפת את פורט ה-MCP של ה-IDE לרשת המקומית, והתעבורה אינה מוצפנת (ws://). הפעילו אותה רק כשחיבור Loopback באמת לא אפשרי; ל-WSL2 העדיפו Mirrored Networking.

עלות ו-Context

העבודה ב-IDE לא מתומחרת אחרת: אותם Tokens, אותו מנוי. שלוש נקודות בכל זאת רלוונטיות:

  • הבחירה בעורך נוספת להקשר. בחירה גדולה בכל Prompt מגדילה את צריכת ה-Context. אם סימנתם אלפי שורות בלי כוונה, הסתירו את הבחירה במחוון.
  • הפעלת Chrome כברירת מחדל טוענת את כלי הדפדפן תמיד, מה שמגדיל את צריכת ה-Context גם כשלא גולשים. אם שמתם לב לעלייה, כבו את ברירת המחדל והשתמשו ב---chrome רק כשצריך.
  • מעקב: /usage בפאנל של VS Code פותח את דוח החשבון והשימוש, כולל פירוק של מה תורם למגבלות התוכנית וטיפים לצמצום.

Best Practices

  • עגנו את Claude ב-Secondary Sidebar לשיחה הראשית, ופתחו לשוניות נוספות למשימות צד.
  • סמנו קוד ולחצו Option+K / Alt+K במקום לתאר מיקומים במילים; אזכור עם טווח שורות מדויק חוסך סבבי הבהרה.
  • התחילו משימות גדולות במצב Plan ונצלו את מסמך ה-Markdown של התוכנית להערות Inline לפני שמאשרים.
  • הוסיפו "$schema": "https://json.schemastore.org/claude-code-settings.json" ל-settings.json כדי לקבל השלמות ואימות בתוך VS Code.
  • ב-JetBrains, טפלו בבעיית ה-ESC מיד אחרי ההתקנה; עצירה אמינה היא בקרת הבטיחות הבסיסית ביותר.
  • השתמשו ב-@terminal:name כדי להזין פלט פקודות ל-Claude במקום להדביק לוגים ידנית.
  • כשצריך פקודה שקיימת רק ב-CLI, אל תוותרו עליה: פתחו את הטרמינל המשולב, הריצו claude --resume והמשיכו את אותה שיחה שם.

Anti-patterns

  • להפעיל Bypass permissions בתוסף על מכונת פיתוח רגילה. ההגדרה allowDangerouslySkipPermissions מיועדת ל-Sandbox בלי גישה לאינטרנט, לא לנוחות יומיומית.
  • לעבוד עם acceptEdits על Repository זר שהורדתם עכשיו. בשילוב עם קובצי תצורת IDE שמורצים אוטומטית, זה מתכון לעקיפת הרשאות.
  • לנהל שני מקורות אמת להגדרות. אל תגדירו משתני סביבה ב-environmentVariables של התוסף אם אותה תצורה צריכה לשרת גם את ה-CLI; שימו אותה ב-~/.claude/settings.json המשותף.
  • להשאיר בחירה ענקית פעילה לאורך שיחה שלמה. ההקשר מתנפח בכל הודעה. בטלו את הסימון או הסתירו את הבחירה כשסיימתם איתה.
  • להקליט GIF של דפדפן עם חשבונות מחוברים ולשתף אותו החוצה. ההקלטה תופסת כל מה שנראה בדפדפן, כולל פרטי חשבון.

תרגיל

תרגיל 27.1: מסלול IDE מלא על TaskFlow

פתחו את פרויקט TaskFlow (examples/taskflow) ב-VS Code (או ב-IDE של JetBrains אם זו הסביבה שלכם) ובצעו:

  1. התקינו את תוסף Claude Code והתחברו.
  2. פתחו את backend/app/routers/tasks.py, סמנו את פונקציית יצירת המשימה בלבד, והוסיפו אזכור עם Option+K / Alt+K. בקשו מ-Claude להסביר מה הפונקציה עושה ואילו קלטים היא לא מוודאת.
  3. עברו למצב Plan ובקשו תוכנית להוספת שדה due_date אופציונלי למשימות. הוסיפו לפחות הערת Inline אחת במסמך התוכנית לפני האישור.
  4. אשרו את התוכנית, עברו ל-Manual, ואשרו את העריכות דרך תצוגת ה-Diff. באחד הקבצים, ערכו משהו קטן ישירות בתצוגת ה-Diff לפני האישור.
  5. השתמשו ב-Rewind (ריחוף מעל הודעה) כדי להחזיר את הקוד לנקודה שלפני השינוי, ואז החזירו אותו קדימה עם בקשה חוזרת או Fork.
  6. לסיום: פתחו את הטרמינל המשולב, הריצו claude --resume, ובחרו את השיחה שניהלתם בפאנל. ודאו שההיסטוריה מלאה.
פתרון מוסבר

שלב 2: אחרי הסימון ולחיצת הקיצור יופיע בתיבת ה-Prompt אזכור בסגנון @backend/app/routers/tasks.py#12-24 (המספרים אצלכם יהיו שונים). Claude יסביר את ה-Endpoint ויציין בין השאר את בעיית האימות של כותרת מרווחים בלבד שהכרנו בפרק 3, אם היא עדיין קיימת אצלכם.

שלב 3: במצב Plan, VS Code פותח את התוכנית כלשונית Markdown. הערה טובה לדוגמה: לבקש שהשדה יהיה Optional[date] עם ברירת מחדל None, ושה-Frontend לא ייכלל בשלב הזה. Claude יעדכן את התוכנית לפי ההערות לפני שמתחיל.

שלב 4: כשעורכים את ההצעה ישירות בתצוגת ה-Diff, Claude מקבל על כך הודעה. שימו לב שהוא מתייחס לגרסה שאישרתם, לא לזו שהציע.

שלב 5: ריחוף מעל ההודעה שקדמה לעריכות, לחיצה על כפתור ה-Rewind ובחירת Rewind code to here מחזירה את הקבצים בלי לאבד את השיחה. Fork conversation and rewind code יוצר ענף נקי אם תרצו לנסות גישה אחרת.

שלב 6: הבוחר של --resume מציג את השיחה עם השם שנוצר לה אוטומטית. זה מדגים שהתוסף וה-CLI חולקים היסטוריה, ולכן אפשר להתחיל בפאנל ולהמשיך בטרמינל כשצריך פקודת CLI ייחודית.

סיכום

  • תוסף VS Code הוא פאנל גרפי מלא עם CLI מובנה משלו: Diffs מקוריים, אזכורי @ עם טווחי שורות מהבחירה, סקירת תוכניות במסמך Markdown עם הערות, Checkpoints עם Rewind, והיסטוריה משותפת עם ה-CLI.
  • תוספת JetBrains (Beta) מריצה את ה-CLI בטרמינל ה-IDE ומוסיפה מציג Diff, שיתוף בחירה ו-Diagnostics; דורשת התקנת CLI נפרדת, ובסביבות Remote מותקנת על ה-Host.
  • /ide מחבר Session מכל טרמינל ל-IDE רץ; claude --resume ממשיך שיחות בין הפאנל לטרמינל; --worktree מבודד משימות מקבילות.
