חלק א | נושא 01

מה זה Rule?

Rule הוא קובץ Markdown קצר בתיקייה .claude/rules/ שמכיל הוראות ל-Claude בנושא אחד. Rule בלי הגבלה נטען בכל Session, כמו CLAUDE.md. Rule עם שדה paths נטען רק כש-Claude עובד על קבצים שמתאימים לתבנית.

בסוף הנושא תדעו: מה ההבדל בין Rule ל-CLAUDE.md, למה Rules חוסכים מקום בשיחה, ומה הם לא עושים.

paths:

מאיפה זה בא. לפי התיעוד של Claude Code, בפרויקט גדול אפשר לחלק את ההוראות לכמה קבצים בתיקייה .claude/rules/. כל קובץ עוסק בנושא אחד, עם שם שמתאר אותו, כמו testing.md או api-design.md. Claude Code מוצא את כל קובצי ה-.md בתיקייה, גם בתתי-תיקיות.

הבעיה ש-Rules פותרים. קובץ CLAUDE.md אחד נטען במלואו בכל Session. כשהוא מכיל גם כללי API, גם כללי React וגם כללי בדיקות, כל Session משלם על הכול, גם כשהעבודה נוגעת רק בחלק אחד. התיעוד ממליץ לשמור כל CLAUDE.md מתחת ל-200 שורות, ולהעביר הוראות שרלוונטיות רק לחלק מהקוד ל-Rules עם paths.

מה Rule לא עושה. Claude מתייחס ל-Rules כמו ל-CLAUDE.md: כהקשר, לא כתצורה שנאכפת. Rule שאומר "אסור לערוך את .env" הוא בקשה. כדי לחסום באמת משתמשים בהרשאות או ב-Hook (נושא 2 ו-10).

איפה Rules עובדים

התיקייה .claude/rules/ היא יכולת של Claude Code: במסוף, בהרחבות ל-IDE ובלשונית Code של אפליקציית שולחן העבודה. בשיחה רגילה באפליקציית Claude (Web, Desktop או Mobile) אין קובצי Rules; המקבילה שם היא ההוראות של Project. Rule שנמצא ב-Repository נוסע איתו לכל מי שמשכפל אותו. Rule שנמצא רק ב-~/.claude/rules/ במחשב שלכם לא קיים במחשבים אחרים.

מתי Rule נטען, ומה קורה לו אחר כך

Rules נטענים בשני רגעים: בפתיחת ה-Session, או ברגע ש-Claude נוגע בקובץ שמתאים לתבנית. מה שנטען נשאר בשיחה, עד שהיא נדחסת.

בסוף הנושא תדעו: מה סדר הטעינה, מה בדיוק מפעיל Rule עם paths, ומה שורד את /compact.

paths:

  1. הוראות ארגוניות (Managed)CLAUDE.md שהארגון מפיץ, או המפתח claudeMd ב-Managed settings. אי אפשר להחריג אותו.בפתיחה

  3. הוראות הפרויקטCLAUDE.md או .claude/CLAUDE.md, וכל Rule בלי paths, באותה עדיפות.בפתיחה
  4. הוראות מקומיותCLAUDE.local.md: אישי לפרויקט הזה, לא נכנס ל-Git.בפתיחה

שום קובץ לא דורס קובץ אחר: כולם מצטרפים להקשר, וה-Rules האישיים נקראים לפני ה-Rules של הפרויקט. אם שני Rules סותרים זה את זה, Claude עלול לבחור באחד מהם באקראי. לכן הפתרון לסתירה הוא למחוק אחד מהם, לא לסמוך על הסדר.

סימולטור Session · לחצו על פעולות לפי הסדר וראו אילו Rules נכנסים להקשר

הסימולציה מבוססת על התיעוד ועל הבדיקה שלנו ב-Claude Code 2.1.300. השמות בסוגריים הם ערכי load_reason ש-Hook מסוג InstructionsLoaded מקבל (נושא 9).

מה בדיוק מפעיל Rule עם paths

  • קריאה, כתיבה או עריכה של קובץ מתאים בכלים Read, Write ו-Edit.
  • הצגת קובץ בודד ב-Bash בפקודה שנחשבת לקריאה, כמו cat או head על קובץ אחד.
  • לא הרצת בדיקות או Build. pytest שרץ על כל התיקייה לא טוען את testing.md; קריאה של קובץ בדיקה כן.
  • אחרי שנטען, ה-Rule נשאר בהקשר עד סוף השיחה. בבדיקה שלנו, Claude המשיך ליישם את כללי ה-API גם כשעבר לדון בקובץ בדיקה.
מה שורד את /compact

לפי התיעוד: CLAUDE.md שבשורש הפרויקט ו-Rules בלי paths נטענים מחדש מהדיסק אחרי דחיסה. Rules עם paths והוראות של תתי-תיקיות נדחסים יחד עם שאר השיחה, ונטענים שוב רק כש-Claude נוגע שוב בקובץ מתאים. אם כלל חייב לשרוד דחיסה, הסירו ממנו את paths או העבירו אותו ל-CLAUDE.md שבשורש.

    פער בין התיעוד לבדיקה

    טבלת הדוגמאות בתיעוד אומרת ש-*.md תופס קובצי Markdown בשורש הפרויקט. בבדיקה שלנו, תבנית בלי / תפסה את שם הקובץ בכל עומק, כמו בקובץ .gitignore. מה שכן עבד כמו שצריך: תבנית עם / באמצע מעוגנת לשורש. ההמלצה שלנו: תמיד לכתוב תבנית עם תיקייה בהתחלה, כמו docs/**/*.md, ולא לסמוך על שם קובץ לבד. ואם צריך רק את השורש, /*.md עבד בבדיקה, אבל הוא לא מתועד.

    חוקי התחביר לפי התיעוד

    • שתי צורות. רשימת YAML (שורה לכל תבנית, עם -), או מחרוזת אחת עם פסיקים. עדיף רשימה, וכל תבנית במירכאות כפולות.
    • סוגריים מסולסלים. {ts,tsx} נפתח לשתי תבניות. כל קבוצה מכפילה: {a,b}/{c,d}/*.{ts,tsx} הן שמונה תבניות. לכל Rule יש תקציב של 1,000 תבניות פתוחות ו-4 MiB; תבנית שחורגת ממנו לא תופסת אף קובץ.
