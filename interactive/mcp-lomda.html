מחברים MCP ל-Claude Code: כלים חדשים, מכל מערכת

MCP (Model Context Protocol) הוא תקן פתוח שבו תוכנה אחת, השרת, חושפת כלים, משאבים ופרומפטים, ותוכנה אחרת, ה-Client, משתמשת בהם. Claude Code הוא Client. בלומדה הזו תכתבו שרת MCP אמיתי בפייתון בשם taskflow-tasks, תחברו אותו ל-Claude Code, תתנו לו הרשאות מדויקות, ותבדקו אותו.

השרת נבדק: לקוח Python SDK קרא לכל היכולות שלו, ו-Claude Code חיבר אותו, קרא לכלי שהתרנו, נעצר בכלי שלא התרנו, קרא משאב והריץ את ה-Prompt שלו כפקודת /.

חלק א | נושא 01

מה זה MCP?

MCP הוא פרוטוקול שבו שרת מצהיר על יכולות, ו-Client מגלה ומשתמש בהן. Claude Code מתחבר לשרת, מקבל את רשימת הכלים שלו, ו-Claude יכול לקרוא להם כמו לכל כלי מובנה, באישור שלכם.

בסוף הנושא תדעו: מה שלושת סוגי היכולות, איך שרת מתחבר, ואיך MCP ב-Claude Code שונה מ-Connectors ב-claude.ai.

client ⇄ server · tools · resources · prompts

הבעיה ש-MCP פותר. Claude Code יודע לקרוא קבצים ולהריץ פקודות. הוא לא יודע לשאול את מערכת הטיקטים שלכם מה פתוח, או לקרוא סכמה ממסד נתונים, בלי שמישהו יכתוב לו דרך. MCP הוא הדרך האחידה: כותבים שרת פעם אחת, וכל Client שתומך בפרוטוקול יכול להשתמש בו.

מה קורה בפועל. כש-Session נפתח, Claude Code מפעיל או פונה לכל שרת מוגדר, ומקבל ממנו רשימה של כלים, משאבים ו-Prompts. הכלים מופיעים ל-Claude בשם mcp__<server>__<tool>. כברירת מחדל רק השמות נטענים, והגדרת הכלי המלאה נטענת כש-Claude צריך אותה (Tool search).

חלק א | נושא 03

Transports, Scopes, ומי גובר

שתי החלטות לכל שרת: איך מתחברים אליו (Transport), ואיפה ההגדרה נשמרת (Scope). ה-Scope קובע מי עוד מקבל את השרת, ומה קורה כשאותו שם מוגדר בכמה מקומות.

בסוף הנושא תדעו: לבחור Transport ו-Scope, ולדעת איזו הגדרה תיבחר כשיש כפילות.

שרתים של project צריכים אישור

במצב אינטראקטיבי, Claude Code שואל לפני שהוא משתמש בשרת מ-.mcp.json, ועד אז claude mcp list מציג ⏸ Pending approval. איפוס הבחירות: claude mcp reset-project-choices. ב-claude -p, ב-Agent SDK ובענן אין את מי לשאול, ולכן השרתים האלה נטענים בלי לשאול. ראינו את זה בבדיקה: ב--p השרת התחבר עם source: project. כדי להשאיר שרת בחוץ: disabledMcpjsonServers, --setting-sources בלי project, או --strict-mcp-config.

תרגיל: כלי שלישי

    
הוסיפו כלי complete_task(task_id: int) שמסמן משימה כ-done. משימה שלא קיימת צריכה להחזיר שגיאה שהמודל יבין.

    
פתרון

      
server.py (תוספת)
@server.tool(description="Mark a task as done by its id.")
def complete_task(task_id: int) -> str:
    tasks = load()
    for t in tasks:
        if t["id"] == task_id:
            t["status"] = "done"
            save(tasks)
            return f"task #{task_id} is done"
    raise ToolError(f"no task with id {task_id}; call list_tasks to see the ids")

      
בדקו עם check_client.py: קריאה עם מזהה קיים, וקריאה עם 999 שמחזירה is_error. ב-Claude Code הכלי יופיע כ-mcp__taskflow__complete_task, וצריך להתיר אותו בנפרד, או עם mcp__taskflow__*.

השרת עולה ידנית, אבל ב-Claude Code הוא Failed to connect

      
בדקו: שהפקודה ב-command היא אותו פייתון שבו התקנתם את mcp (ה-venv, לא python3 של המערכת); שהנתיב נכון ביחס לתיקיית הפרויקט; ושהשרת לא מדפיס כלום ל-stdout לפני הפרוטוקול. להפעלה איטית: MCP_TIMEOUT=20000 claude.

    

    
הכלי מופיע ב-/mcp, אבל Claude לא יכול לקרוא לו

      
שלוש סיבות מהתיעוד: השם המלא ארוך מ-128 תווים, ו-Claude Code משמיט אותו; ה-Input schema לא תקין, ו-Claude Code משמיט את הכלי ורושם את הסיבה ביומן של השרת; או כלל deny שתופס אותו. קצרו את שם השרת או הכלי, ותקנו את הסכמה.

הכלל שכתבתי ב-allow לא עובד

      
בדקו: כלל allow עם Glob חייב להתחיל ב-mcp__<server>__ מילולי, ו-mcp__* או * ב-allow נדחים עם אזהרה. כלל mcp__ עם סוגריים מדולג כשקובץ ההגדרות נטען. לשרת מ-Plugin השם הוא mcp__plugin_<plugin>_<server>__<tool>.

    

    
משתנה סביבה לא הגיע לשרת

      
בדקו: שהמשתנה מוגדר ב-Shell שממנו הפעלתם את claude; שאין רשומה באותו שם ב-Scope גובר, כי שדות לא מתמזגים; ושלא מדובר במשתנה של אישורים, כמו ANTHROPIC_API_KEY, שנקרא ריק ב-url וב-headers של שרת מרוחק.

    

    
תוצאה גדולה נחתכת או נשמרת לקובץ
