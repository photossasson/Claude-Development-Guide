Mod הוא Plugin שמכיל פונקציות JavaScript או TypeScript, ו-Claude Code קורא להן כשאירוע קורה: קריאה לכלי, שליחת פרומפט, ציור של חלק בממשק. בלומדה הזו תבנו Mod אמיתי בשם risk-guard, שעוצר פקודות Bash שקשה לבטל, שואל אתכם אם להמשיך, סופר מה נעצר ומציג את זה מעל שורת הפרומפט.

למי הלומדה מתאימה

למי שכבר עובד עם Claude Code ורוצה לשנות את ההתנהגות או את הממשק שלו: לחסום, לשכתב, להוסיף פקודה או פאנל. צריך לקרוא JavaScript או TypeScript ברמה בסיסית. Mods הם תכונה חדשה (גרסה 2.1.287 ומעלה), ולכן הם עדיין לא מופיעים בפרקי המדריך שנכתבו לפניהם. הלומדה משלימה את פרק 26: Plugins ואת הלומדה על Hooks, שמסבירה את ה-Hooks שבקובצי ההגדרות.

שימו לב: זו לא אותה מילה

בתיעוד של Claude Code שני דברים נקראים Hook. Settings hook הוא פקודת Shell, בקשת HTTP או פרומפט שמוגדרים ב-settings.json. Hook של Mod הוא פונקציה שרצה בתוך Claude Code. בלומדה הזו "Hook" הוא תמיד הסוג השני, ו"Settings hook" הוא הסוג הראשון.

חלק א | נושא 01

מה זה Mod?

Mod הוא Plugin שהקוד שלו רושם פונקציות לאירועים. כשהאירוע קורה, Claude Code קורא לפונקציה לפני שהוא פועל, והפונקציה מחליטה מה קורה: להמשיך כרגיל, לשנות את האירוע, או לענות במקום Claude Code.

בסוף הנושא תדעו: מאילו שלושה קבצים בנוי Mod, מה שלושת הארגומנטים של כל Hook, ומה שלוש הדרכים לטפל באירוע.

on(event, matcher, ($, e, next))

ההגדרה מהתיעוד. Mod הוא Plugin שמשנה איך Claude Code נראה ומתנהג. הוא בנוי מ-Event handlers ב-JavaScript או ב-TypeScript: Claude Code קורא ל-Handler כשקורה אירוע, כמו קריאה לכלי, פרומפט שנשלח או חלק בממשק שמצויר, וה-Handler יכול לצפות באירוע, לשנות אותו או לקחת אותו לידיו.

מה זה מוסיף. Settings hooks, Skills, Status lines ושרתי MCP פועלים מבחוץ: מריצים סקריפט, או נותנים ל-Claude טקסט וכלים. Mod רץ בתוך Claude Code, ולכן הוא יכול לצייר פאנל או פס מעל הפרומפט, לצייר מחדש חלקים מהממשק של Claude Code, להחזיק קריאה לכלי בזמן שהוא שואל אתכם שאלה, להוסיף פקודת / שרצה מיד בלי תור של Claude, ולשתף נתונים בין Hooks.

המפתח modules ב-hooks/hooks.json הוא מה שהופך Plugin ל-Mod. הוא מכיל נתיב אחד, יחסי לקובץ. אין צורך ב-Node.js, ב-Bundler או בשלב Build: Claude Code טוען קובצי .js ו-.ts ישירות.

hooks/register.js
let calls = 0

export function register(on) {
  on('tool.call', async ($, e, next) => {
    calls += 1
    $.ui.invalidate('ui.render')
    return next(e)
  })

  on('ui.render', { component: 'Spinner' }, async ($, e, next) => {
    return next({ ...e, props: { ...e.props, suffix: ' · tool calls: ' + calls + '…' } })
  })
}

ה-Hook הראשון סופר כל קריאה לכלי ומבקש ציור מחדש. השני מוסיף את המספר אחרי המילה של ה-Spinner, למשל Thinking · tool calls: 3….

Rewrite
on('tool.call', { tool: 'Bash' }, async ($, e, next) =>

קוראים ל-next עם עותק משונה של e. כל מה שמתחת רואה את הגרסה החדשה, בגבולות מה שהאירוע מתיר לשנות.

Answer
on('tool.call', { tool: 'Edit' }, async ($, e, next) =>
  /\.env$/.test(e.file_path)
    ? { deny: 'This file is protected.' }   // the tool never runs
    : next(e)
)

מחזירים תוצאה בלי לקרוא ל-next. כאן זו חסימה, וב-command.run זה הטקסט של הפקודה.

איפה Mods קיימים, ואיפה לא

Mods הם של Claude Code בלבד: ה-CLI, כולל טרמינל בתוך עורך ו-JetBrains, ולשונית Code באפליקציית Claude Desktop. לשיחה רגילה באפליקציית Claude או ב-claude.ai אין Mods, וגם לא ל-Claude API. ב-Agent SDK ה-Hooks של Mod רצים, אבל מה שהוא מצייר לא מוצג (נושא 8). ל-Agent SDK יש גם מנגנון Hooks משלו, כ-Callbacks בקוד, שהלומדה לא עוסקת בו.

אירועים, ומה Hook יכול לענות בכל אחד

לכל אירוע יש קלט, ויש תוצאה שה-Hook מחזיר. בחלק מהאירועים התוצאה יכולה לסרב: לחסום כלי, להפיל פרומפט, לא לטעון Mod אחר. אלה ה-Hooks ש-claude plugin validate מסמן כ-gating hook.

האירועים המרכזיים · לחצו על אירוע לפרטים

זו בחירה של האירועים השימושיים ביותר, לא רשימה מלאה. הרשימה המלאה של הגרסה שלכם נמצאת בקובץ ההגדרות שהמנוע כותב ליד ה-Mod (נושא 9), ב-Mods reference.

Matchers · מסננים לפני שה-Hook רץ

ה-Matcher הוא אובייקט, הארגומנט השני של on. כל שדה בו נבדק מול השדה באותו שם בקלט של האירוע. ערך יכול להיות ערך בודד, מערך (אחד מהם) או ביטוי רגולרי. Hook בלי Matcher רץ בכל מופע של האירוע.

דוגמאות
on('tool.call', { tool: 'Bash' }, hook)                    // one tool
on('tool.call', { tool: ['Edit', 'Write'] }, hook)         // either tool
on('tool.call', { tool: /^mcp__github__/ }, hook)          // a regex
on('command.run', { command: 'guard-status' }, hook)       // one command
on('ui.render', { component: 'Pane', requestId: 'stats' }, hook)
on('ui.render', { props: { origin: { kind: 'task-notification' } } }, hook)
טיפוסים לפי כלי

ב-TypeScript, Matcher כמו { tool: 'Bash' } מצמצם את e: העורך יודע ש-e.command קיים. הטבלה של הכלים המובנים נכתבת ליד ה-Mod, בקובץ .claude-plugin/types/claude-code-tools/index.d.ts.

הדוגמה שנבנה: risk-guard

Mod אחד שמדגים את שלוש הדרכים: Hook שעונה (חוסם) על קריאה לכלי, Hook שעונה על פקודה, ו-Hook שמצייר. כל קובץ כאן הוא הקובץ שבדקנו.

בסוף הנושא תדעו: מה כל קובץ עושה, איך ה-State עובר בין ה-Hooks, ואיך מריצים את ה-Mod.

on(event, matcher, ($, e, next))

הבעיה. יש פקודות Bash שאי אפשר לבטל: rm -rf, git push --force, git reset --hard, git clean -f. כלל ask בהרשאות שואל על כל פקודה שתואמת לתבנית, אבל קשה לכתוב תבנית שתופסת את כל הצורות של rm עם דגלים.

הפתרון. Hook על tool.call של Bash שבודק את הפקודה בביטוי רגולרי. פקודה מסוכנת מחכה: ה-Mod שואל "Allow once" או "Block". כשאין את מי לשאול, כמו ב-claude -p, הוא חוסם. אפשרות mode ב-plugin.json מאפשרת לבחור deny, חסימה בלי לשאול.

סימולטור: מה יקרה לפקודה? · זהו תרגום לדפדפן של risk.ts ושל השומר

mode ב-plugin.json
מה קורה כשה-Mod שואל

    למה להחליט לפני next

    ה-.catch מקבל את next.called: האם ה-Hook כבר קרא ל-next לפני שנכשל. אם לא, ה-Handler מחזיר { deny }, והכלי לא רץ. אם כן, next(e) בתוך ה-Handler מחזיר את מה שהקריאה הקודמת כבר החזירה, ושום דבר לא רץ פעמיים. לכן שומר טוב בודק ומחליט לפני next.

    ל-Hook יש עשר שניות של זמן משלו לכל הפעלה. הזמן נעצר בזמן ש-next או קריאה ל-$ רצים, ולכן ההמתנה לתשובה שלכם ב-$.ui.ask לא נספרת. ל-.catch יש שנייה אחת.

    הצורה של התוצאה ב-tool.call

    מה מחזיריםמה קורה
    next(e)הכלי רץ כרגיל. אפשר לחכות לתוצאה (await next(e)) ולפעול לפיה, למשל לבדוק isError.
    next({ ...e, command })הכלי רץ עם קלט משוכתב. Settings hooks מנוהלים רצים שוב על הקלט החדש.
    { deny: 'why' }הכלי לא רץ. Claude מקבל את הטקסט כתוצאה שגויה, ובתמליל מופיע tool_use_error.
