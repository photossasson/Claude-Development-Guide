בונים Skill ב-Claude, מהרעיון ועד בדיקה

בלומדה הזו תבנו Skill אמיתי ושלם, שלב אחר שלב: תיקייה עם קובץ SKILL.md, קובץ עזר וסקריפט שרץ. תתקינו אותו ב-Claude (באפליקציה, ב-Claude Code או בשניהם), תבדקו שהוא עובד, ותדעו לתקן אותו כשהוא לא.

ה-Skill לדוגמה נקרא checking-hebrew-style. הוא בודק טקסט טכני בעברית ומוצא מקפים ארוכים, רווחים כפולים ופיסוק שגוי סביב מונחים באנגלית. בחרנו בו כי הוא קטן מספיק להבנה מלאה, שימושי באמת, והוא עובד גם באפליקציית Claude וגם ב-Claude Code.

למי הלומדה מתאימה

למי שמשתמש ב-Claude ורוצה ללמד אותו לעבוד בדרך קבועה. אין צורך לדעת לתכנת: אפשר ליצור Skill בשיחה עם Claude (נושא 7). מי שעובד עם Claude Code יקבל בנוסף את כל הפקודות להתקנה ולבדיקה מהמסוף. זו לומדה משלימה לפרק 21: Skills במדריך, שמעמיק בכל שדות ה-Frontmatter ובחמישה Skills נוספים.

חלק א | נושא 01

מה זה Skill?

Skill הוא תיקייה עם הוראות, ולפעמים גם קבצי עזר וסקריפטים, ש-Claude טוען רק כשהמשימה שלכם מתאימה לה. כותבים את הנוהל פעם אחת, ו-Claude מיישם אותו בכל פעם שצריך.

בסוף הנושא תדעו: ממה בנוי Skill, למה הוא חוסך עבודה ומקום בשיחה, ואילו שלושה מונחים חוזרים לאורך כל הלומדה.

---

ההגדרה הרשמית בקצרה. לפי Anthropic, Skills הם תיקיות של הוראות, סקריפטים ומשאבים ש-Claude טוען באופן דינמי כדי לבצע טוב יותר משימות מתמחות. כל Skill מחזיק לפחות קובץ אחד: SKILL.md. בראש הקובץ יש כמה שורות מידע (שם ותיאור), ומתחתן ההוראות עצמן.

הבעיה ש-Skill פותר. אם אתם מדביקים שוב ושוב את אותן הוראות לשיחה, מתקנים את Claude באותו תיקון בכל פעם, או מסבירים לו נוהל של כמה שלבים מחדש, זה בדיוק המקום ל-Skill. התיעוד של Claude Code מגדיר את המצבים האלה כסימן ליצירת Skill.

למה זה זול. Claude לא קורא את כל ה-Skills בכל שיחה. בהתחלה הוא רואה רק את השם והתיאור של כל Skill. את ההוראות המלאות הוא קורא רק כשהבקשה שלכם מתאימה לתיאור, ואת קבצי העזר רק כששלב מסוים מבקש אותם. לכן אפשר להתקין הרבה Skills בלי שהשיחה תתמלא.

שלושה מונחים שחוזרים בכל הלומדה · לחצו על כרטיס כדי לקרוא

אנלוגיה מהחיים

חשבו על מטבח של מסעדה. על הקיר תלוי לוח עם שמות כל המתכונים ושורה קצרה על כל אחד. הטבח לא קורא את כל ספר המתכונים לפני כל מנה: הוא מסתכל בלוח, מזהה את המתכון המתאים להזמנה, ורק אז פותח את הדף המלא. ה-Frontmatter הוא השורה בלוח, גוף SKILL.md הוא דף המתכון, וקבצי העזר הם הנספחים שפותחים רק כשמגיעים לשלב שצריך אותם. זו אנלוגיה שלנו, לא ציטוט מהתיעוד.

חלק א | נושא 02

מתי Skill, ומתי כלי אחר?

ל-Claude יש כמה דרכים "ללמוד" משהו. Skill הוא הנכון כשמדובר בנוהל שחוזר על עצמו. לעובדה קבועה, לאכיפה מוחלטת או למידע חי ממערכת אחרת יש כלים מתאימים יותר.

בסוף הנושא תדעו: לבחור בין Skill, הוראות קבועות, Hook, MCP או Connector, Subagent ו-Plugin, ולדעת באיזה מוצר כל אחד קיים.

חלק א | נושא 03

איך Skill נטען, ואיפה הוא עובד

Claude טוען Skill בשלוש רמות, ורק מה שצריך. ומאחר ש-Skills קיימים בכמה מוצרים של Claude, חשוב לדעת איפה כל Skill חי ואיפה לא.

בסוף הנושא תדעו: מה נכנס לשיחה ומתי, איך מפעילים Skill אוטומטית וידנית, ומה ההבדלים בין אפליקציית Claude, Claude Code ו-Claude API.

---

שלוש רמות הטעינה · לחצו על רגע בשיחה וראו מה נכנס להקשר

רמה 1: Metadata. השם והתיאור של כל Skill מותקן.~100 tokens / Skill
רמה 2: ההוראות. גוף SKILL.md, רק של ה-Skill שהופעל.< 5k tokens
רמה 3: משאבים. rules.md נקרא כשצריך. הסקריפט רץ, ורק הפלט שלו נכנס.0 עד שנקרא

המספרים מתוך דף ה-Overview של Agent Skills בתיעוד הפלטפורמה. הם הערכות סדר גודל, לא מדידה של ה-Skill שלנו.

שתי דרכים להפעיל Skill

אוטומטית

כותבים בקשה רגילה, ו-Claude משווה אותה לתיאורים של ה-Skills. אם יש התאמה, הוא טוען את ה-Skill בעצמו. באפליקציה רואים בחשיבה של Claude שהוא משתמש ב-Skill. זו הדרך העיקרית באפליקציה.

ידנית, עם /

ב-Claude Code מקלידים / ואת שם ה-Skill בתחילת ההודעה, למשל /checking-hebrew-style. גם בלשונית Code של אפליקציית שולחן העבודה מקלידים / בתיבת הבקשה, או לוחצים על + ובוחרים Slash commands.

סנכרון מהאפליקציה ל-Claude Code

Skills שהפעלתם בחשבון Claude נטענים גם ב-Claude Code במסוף, כשנכנסים לאותו חשבון. זה דורש Claude Code בגרסה 2.1.273 ומעלה. הסנכרון חד-כיווני: הוא קורא מהחשבון ולא משנה בו דבר. ב-Claude Code רואים אותם בפקודה /skills תחת claude.ai sync. בכיוון ההפוך אין סנכרון: Skill שיושב רק ב-~/.claude/skills/ במחשב לא מופיע באפליקציה, וגם לא בשיחות ענן של Claude Code.

מקורות שאינם מסכימים

דף ה-Overview בתיעוד הפלטפורמה עדיין כותב ש-Skills לא מסתנכרנים בין מוצרים, שהעלאה נעשית ב-Settings > Features, ושאין שיתוף ארגוני. התיעוד של Claude Code ומאמרי העזרה העדכניים (עודכנו לפני כ-3 שבועות) מתארים סנכרון לטרמינל, מסך Customize > Skills ושיתוף ב-Team וב-Enterprise. הלומדה פועלת לפי המקורות העדכניים יותר, ומציינת את הפער.

חלק ב | נושא 04

הדוגמה שנבנה: תיקייה אחת, שלושה קבצים

ה-Skill checking-hebrew-style מדגים את שלושת סוגי התוכן ש-Skill יכול להחזיק: הוראות, קובץ עזר וסקריפט. כל קובץ כאן הוא הקובץ האמיתי שנבדק, לא דוגמה מקוצרת.

בסוף הנושא תדעו: מה תפקיד כל קובץ, למה הם מחולקים כך, ואיך ליצור את התיקייה בעצמכם.

---

הבעיה. בטקסט טכני בעברית קל לפספס שגיאות קטנות: מקף ארוך שנראה כמו מקף רגיל, רווח כפול, פסיק בלי רווח אחריו, או ה - Skill במקום ה-Skill. אלה בדיוק הכללים שהמדריך הזה מקפיד עליהם. Claude יכול לבדוק אותם בעין, אבל סקריפט בודק כל תו ולא מתעייף.

הפתרון. Skill שבו ההוראות אומרות ל-Claude מתי ואיך לעבוד, קובץ העזר מסביר כל כלל עם דוגמאות לפני ואחרי, והסקריפט מוצא את השגיאות במדויק. Claude מתקן ומריץ שוב, עד שאין ממצאים.

סייר הקבצים · לחצו על קובץ כדי לראות את התוכן ואת התפקיד שלו

checking-hebrew-style/ references/ scripts/

יוצרים את התיקייה במחשב · למי שעובד עם Claude Code

מריצים במסוף. הפקודה יוצרת את מבנה התיקיות בתוך התיקייה האישית של ה-Skills, כך שה-Skill יהיה זמין בכל הפרויקטים שלכם במחשב הזה.

Terminal
mkdir -p ~/.claude/skills/checking-hebrew-style/references ~/.claude/skills/checking-hebrew-style/scripts

התוצאה: שלוש תיקיות ריקות. בשלב הבא שומרים בהן את שלושת הקבצים מסייר הקבצים, בדיוק בשמות שמופיעים שם. אין סיכון בפקודה: היא רק יוצרת תיקיות, ולא מוחקת דבר אם הן כבר קיימות.

מריצים ב-PowerShell. $HOME הוא התיקייה האישית שלכם, ושם Claude Code מחפש את .claude\skills.

PowerShell
New-Item -ItemType Directory -Force -Path "$HOME\.claude\skills\checking-hebrew-style\references", "$HOME\.claude\skills\checking-hebrew-style\scripts"

הדגל -Force מונע שגיאה אם התיקיות כבר קיימות. הסקריפט של ה-Skill נקרא עם python3. ב-Windows ודאו ש-Python 3 מותקן; אם הפקודה אצלכם היא py או python, Claude יכול להריץ אותה כך כשתבקשו.

לא עובדים עם מסוף?

אין צורך. באפליקציית Claude מעלים קובץ ZIP של התיקייה (נושא 8), או מבקשים מ-Claude לבנות את ה-Skill בשיחה (נושא 7). קובץ ה-ZIP המוכן של הדוגמה נמסר יחד עם הלומדה, ונשמר בפרויקט בתיקייה skills/checking-hebrew-style/.

      "תיקנתי את כל 9 הממצאים ב-sample-bad.md, והרצה חוזרת של הבודק מחזירה 0 ממצאים. [...] השארתי את בלוק הקוד, את ה-inline code ואת ה-URL בלי שינוי, כי הבודק מדלג עליהם."

      ההרצות נעשו במצב לא-אינטראקטיבי עם הרשאות מצומצמות: הרצת python3, קריאה ועריכה בלבד. באפליקציית Claude לא בדקנו בפועל; הצעדים שם מבוססים על מאמרי העזרה.

      בקשות בדיקה ל-Skill שלנו · כאלה שצריכות להפעיל אותו, וכאלה שלא

      בקשהצפוילמה
      "תבדוק את הפיסוק והמקפים בפרק הזה"מפעילפיסוק ומקפים בטקסט עברי, בדיוק לפי התיאור

      לולאת השיפור

      1. קודםמריצים כל בקשת בדיקה ב-Session חדש, פעם עם ה-Skill ופעם בלעדיו. Session חדש חשוב: הקשר שנשאר מכתיבת ה-Skill מסתיר חורים בהוראות.
      2. אם הוא לא מופעל כשצריךמוסיפים לתיאור את המילים שמשתמשים באמת כותבים.
      3. אם הוא מופעל כשלא צריךמחדדים את התיאור. ב-Claude Code אפשר גם להוסיף disable-model-invocation: true, ואז רק אתם מפעילים אותו עם /. השדה הזה אינו בתקן, ולכן לא נכנס לגרסה שמעלים לאפליקציה.
      4. אם התוצאה לא טובהמחזקים את ההוראות בגוף, מוסיפים דוגמה, או מעבירים עבודה מדויקת לסקריפט. skill-creator מריץ את ההשוואה הזו אוטומטית: בצ'אט אחת אחת, וב-Cowork וב-Claude Code גם מול גרסה בלי Skill, עם אחוזי הצלחה, זמנים ו-Tokens.

      פתרון תקלות · לחצו על התקלה שלכם

      ה-Skill לא מופעל אוטומטית

      1. ודאו שהוא דולק ב-Customize > Skills, או שהוא מופיע ב-/skills ב-Claude Code. 2. בדקו שהתיאור כולל מילים שאתם באמת כותבים. 3. נסחו את הבקשה קרוב יותר לתיאור, או בקשו במפורש "השתמש ב-Skill של בדיקת הסגנון". 4. ב-Claude Code הפעילו ישירות עם /checking-hebrew-style.

      אם הפעלה ישירה עובדת ואוטומטית לא, הבעיה בתיאור, לא בגוף.

      הפעלה ידנית עובדת, אבל Claude לא "רואה" את התיאור

      ב-Claude Code, אם ה-YAML שבור, ה-Skill נטען עם גוף אבל בלי שדות. /checking-hebrew-style עובד, אבל אין תיאור להתאים אליו. מריצים claude --debug ומחפשים את שגיאת הפענוח, או claude plugin validate ~/.claude/skills. סיבה נפוצה: נקודתיים בתוך התיאור בלי מרכאות, או שה---- הראשון אינו השורה הראשונה בקובץ.

      ההעלאה לאפליקציה נכשלת

      הסיבות שמאמר העזרה מונה: ZIP גדול מדי, שם התיקייה לא תואם לשם ה-Skill, חסר קובץ SKILL.md, או תווים לא חוקיים בשם או בתיאור. בדקו גם שה-ZIP מכיל את התיקייה בשורש, ושאין שדות Frontmatter שאינם בתקן. שדה כזה מחזיר שגיאה בסגנון Unexpected key(s) in SKILL.md frontmatter.

      אין מסך Skills, או שה-Skills אפורים

      הרצת הקוד כבויה. ב-Free, Pro ו-Max: Settings > Capabilities. ב-Team וב-Enterprise: פנו לבעלים של הארגון. אם חסרה האפשרות ליצור או להעלות, ייתכן שהארגון כיבה את User-created skills.

      הסקריפט לא רץ

      ב-Claude Code הרצת סקריפט היא פקודת Bash, ולכן היא דורשת אישור. אשרו אותה, או הוסיפו כלל הרשאה מתאים. ב-Windows ודאו ש-Python 3 מותקן. אם הבודק מחזיר קוד 2, הקובץ לא נמצא או לא שמור ב-UTF-8: ההודעה אומרת מה מהשניים.

      Claude הפסיק לעקוב אחרי ה-Skill באמצע

      ב-Claude Code, תוכן ה-Skill נכנס לשיחה פעם אחת ולא נקרא שוב. אחרי דחיסת השיחה נשמרים רק 5,000 ה-Tokens הראשונים של כל Skill. הפעילו את ה-Skill שוב, ושמרו את ההוראות החשובות בראש הקובץ.

      ערכתי את ה-Skill וההתנהגות לא השתנתה

      באפליקציה: העלו מחדש את הגרסה המעודכנת. ב-Claude Code: שינוי בקובץ נקלט לבד, אבל תוכן שכבר הופעל בשיחה נשאר כמו שהוא. הפעילו את ה-Skill שוב, או פתחו Session חדש.

      תרגיל 9.1: שלוש בקשות שלא אמורות להפעיל

      כתבו שלוש בקשות שקרובות לנושא של ה-Skill, אבל לא אמורות להפעיל אותו. אחר כך הריצו אותן ב-Session חדש ובדקו.

      פתרון מוסבר

      1. "תסביר לי מתי משתמשים בנקודתיים בעברית" (שאלת ידע, אין קובץ). 2. "תכתוב לי פסקה חדשה על Hooks" (כתיבה מאפס, לא בדיקה). 3. "תבדוק את הקוד ב-check_style.py" (בדיקת קוד, לא טקסט עברי).

      הבקשה השנייה היא מקרה גבול, כי "writing" מופיע בתיאור. אם Claude מפעיל את ה-Skill עליה, אפשר להחליט שזה רצוי (בדיקה אחרי כתיבה), או להוריד את "writing" מהתיאור. זו בדיוק ההחלטה שבדיקות כאלה נועדו לחשוף.
