בונים Hooks ב-Claude Code: מה שחייב לקרות, קורה תמיד

בלומדה הזו תבנו שני Hooks אמיתיים: אחד שחוסם עריכה של קבצים רגישים לפני שהיא קורית, ואחד שבודק כל קובץ טקסט אחרי עריכה ומחזיר ל-Claude את הממצאים לתיקון. תלמדו לבחור אירוע, לכתוב Matcher, לקרוא קלט ב-stdin ולהחזיר החלטה, ולבדוק שהכול עובד.

שני ה-Hooks נבדקו ב-Claude Code: הראשון עצר עריכה של .env, והשני גרם ל-Claude לתקן קובץ עד שלא נשארו בו שגיאות סגנון. ה-Hook השני מריץ את אותו בודק שבנינו בלומדה על Skills.

למי הלומדה מתאימה

חלק א | נושא 01

מה זה Hook?

Hook הוא פקודה שאתם מגדירים, ש-Claude Code מריץ אוטומטית ברגע קבוע: לפני שכלי רץ, אחרי עריכה, בפתיחת Session, כש-Claude מסיים לענות ועוד. ה-Hook רץ מחוץ למודל, ולכן הוא קורה תמיד.

בסוף הנושא תדעו: ממה בנוי Hook, מה ההבדל בינו לבין הוראה, ואילו חמישה מונחים חוזרים בכל הלומדה.

event → matcher → handler

ההגדרה מהתיעוד. Hooks הם פקודות Shell שהמשתמש מגדיר, ו-Claude Code מריץ אותן בנקודות מסוימות במחזור החיים שלו. הם נותנים שליטה דטרמיניסטית: פעולות מסוימות תמיד קורות, במקום לסמוך על המודל שיבחר להריץ אותן.

הבעיה ש-Hooks פותרים. הוראה ב-CLAUDE.md או ב-Rule, כמו "הרץ את הבודק אחרי כל עריכה", היא בקשה. ברוב המקרים Claude יציית, אבל לא תמיד. Hook הוא קוד: הוא לא שוכח, לא מתווכח, ולא תלוי בהקשר של השיחה.

איך זה נראה. ב-settings.json רושמים: באירוע הזה (PreToolUse), כשהכלי הוא זה (Edit|Write), הרץ את הפקודה הזו. כשהאירוע קורה, Claude Code שולח לפקודה את פרטי האירוע כ-JSON ב-stdin, והפקודה עונה בקוד יציאה, ולפעמים ב-JSON ב-stdout.

חמישה מונחים שחוזרים בכל הלומדה · לחצו על כרטיס כדי לקרוא

הוראה מול Hook · אותה דרישה, שתי תוצאות

הוראה ב-RuleHook
"Never edit .env". Claude בדרך כלל יציית. בשיחה ארוכה ועמוסה, הסיכוי לטעות עולה.PreToolUse על Edit|Write שבודק את הנתיב. העריכה לא קורית, ו-Claude מקבל נימוק.
"Run the style checker after every edit". לפעמים יקרה, לפעמים לא.PostToolUse שמריץ את הבודק אחרי כל עריכה, ומחזיר ל-Claude את הממצאים.
אין דרך לדעת אם ההוראה יושמה.יש תיעוד: הצלחה שקטה, חסימה עם הודעה, או שגיאה שמופיעה בתמליל.
איפה Hooks עובדים

ה-Hooks בלומדה הזו הם של Claude Code: הם מוגדרים בקובצי settings.json, בתוך Plugin, או ב-Frontmatter של Skill או של Subagent, ורצים במחשב שבו Claude Code רץ. לשיחה רגילה באפליקציית Claude אין Hooks. ב-Agent SDK יש מנגנון Hooks משלו, שמוגדר בקוד כפונקציות (callbacks); הלומדה לא עוסקת בו.

חלק א | נושא 02

מתי Hook, ומתי כלי אחר?

Hook הוא הכלי הנכון כשמשהו חייב לקרות או להיחסם בכל פעם, ותלוי בתוכן הפעולה. לחסימה גורפת יש הרשאות, ולידע ולנהלים יש Rules ו-Skills.

בסוף הנושא תדעו: לבחור בין Hook, הרשאות, Rule ו-Skill, ולבחור את האירוע הנכון ל-Hook.

event → matcher → handler
כליאופימתי לבחור בודוגמה
Rule או CLAUDE.mdהנחיה, תלויה בשיקול הדעת של Claudeסגנון, מוסכמות, ידע על הפרויקט"Validate request bodies with Pydantic"

הרשאות ו-Hook עובדים יחד

כלל deny יודע לחסום את הכלי Edit על נתיב מסוים. רק Hook יודע להחליט לפי מה שכתוב בתוכן, כי הוא קוד שבודק את הקלט בפועל. ובכיוון ההפוך: Hook שמחזיר allow לא עוקף כלל deny. התיעוד מציע גם שילוב: לאפשר את Bash בהרשאות, ולהוסיף Hook מסוג PreToolUse שדוחה רק פקודות מסוימות.

תרגול: מה הכלי, ואיזה אירוע? · בחרו תשובה לכל מצב

מתי לא לכתוב Hook

  • העדפה רכה. "Prefer named exports" שייך ל-Rule.
  • חסימה גורפת של כלי או פקודה. כלל deny עושה את זה בלי סקריפט.
  • החלטה שדורשת שיקול דעת אנושי. השאירו את דיאלוג האישור. Hook מסוג PermissionRequest עם Matcher ריק מאשר הכול, ובפועל מבטל את מערכת ההרשאות.
  • עבודה איטית על כל פעולה. Hook סינכרוני מעכב כל תור. להרצת כל הבדיקות עדיף Stop, או Hook שרץ ברקע עם async.

חלק ב | נושא 04

הדוגמה שנבנה: שומר לפני, בודק אחרי

שני Hooks שמדגימים את שתי הדרכים לענות: protect_files.py חוסם עם JSON לפני עריכה, ו-hebrew_style_gate.py מחזיר משוב עם קוד 2 אחרי עריכה. כל קובץ כאן הוא הקובץ שבדקנו.

בסוף הנושא תדעו: מה כל קובץ עושה, למה הם כתובים ב-Python, ואיך מתקינים אותם בפרויקט.

event → matcher → handler

הבעיה. יש קבצים ש-Claude לא אמור לערוך בכלל: .env עם סיסמאות, קובצי Lock שמתעדכנים רק דרך מנהל החבילות, מה שבתוך .git/. ויש כללי סגנון שכדאי לבדוק אחרי כל עריכה של מסמך, לא רק כשזוכרים.

הפתרון. Hook לפני עריכה שבודק את הנתיב ומחזיר deny עם נימוק. Hook אחרי עריכה שמריץ את הבודק מה-Skill על קובצי טקסט, ואם יש ממצאים, מחזיר אותם ל-Claude כדי שיתקן. בחרנו ב-Python עם הספרייה הסטנדרטית בלבד: אין צורך ב-jq, והקוד זהה ב-macOS, ב-Linux וב-Windows.

סייר הקבצים · לחצו על קובץ כדי לראות את התוכן ואת התפקיד שלו

.claude/ hooks/

התקנה בפרויקט · מתוך שורש הפרויקט

  1. יוצרים את התיקייה ומעתיקים אליה את שני הסקריפטים מסייר הקבצים, ואת check_style.py מה-Skill:
    Terminal
    mkdir -p .claude/hooks

  2. ממזגים את התוכן של settings.json לתוך .claude/settings.json. אם כבר יש שם מפתח hooks, מוסיפים את האירועים בתוכו, לא מחליפים אותו.
  3. בודקים ידנית לפני הכול (נושא 9), ואז פותחים Claude Code ומקלידים /hooks.

ב-Windows הפקודה של Python היא לעתים py או python ולא python3. במקרה כזה החליפו את הערך של "command" ב-settings.json. ה-Hooks רשומים ב-Exec form (עם args), שעובד ב-Windows כש-command הוא קובץ הרצה אמיתי כמו python.exe.

מה קרה בבדיקה

ריצה 1: ביקשנו להוסיף שורה ל-.env. Claude ניסה קודם echo >> .env ב-Bash, ומערכת ההרשאות עצרה אותו. אחר כך ניסה Edit, ו-protect_files.py החזיר deny. Claude עצר והסביר לנו איזו פקודה להריץ בעצמנו. הקובץ לא השתנה. ריצה 2: ביקשנו ליצור מסמך עם מקף ארוך ורווח כפול. ה-Write הצליח, ה-Hook החזיר 2 עם הממצאים, ו-Claude כתב את הקובץ מחדש בתור הבא. בסוף: אפס ממצאים.

מה ריצה 1 מלמדת

ה-Hook מכסה רק את הכלים שה-Matcher תופס. Claude יכול לנסות לשנות קובץ גם דרך Bash. בריצה שלנו מערכת ההרשאות עצרה את זה, כי Bash לא היה מאושר. לכן מגינים בשכבות: Hook, כללי deny, ו-Sandbox כשצריך.

חלק ב | נושא 05

settings.json ו-Matchers

ההגדרה בנויה בשלוש רמות: אירוע, קבוצה עם Matcher, ומטפלים. Matcher שגוי פירושו Hook שלא רץ, או שרץ על כל דבר.

בסוף הנושא תדעו: לקרוא ולכתוב את מבנה ההגדרה, לכתוב Matcher מדויק, ולסנן לפי ארגומנטים עם if.

event → matcher → handler

ההגדרה של protect_files.py · כל שורה וההסבר שלה

בודק Matchers · כתבו Matcher ושם כלי וראו אם ה-Hook ירוץ

חוקי ה-Matcher לפי התיעוד

ערךאיך נבדקדוגמה
"*", "" או בלי Matcherהכולרץ בכל מופע של האירוע
רק אותיות, ספרות, _, -, רווחים, , ו-|שם מדויק, או רשימת שמותEdit|Write ו-Edit, Write זהים
כל תו אחרביטוי רגולרי של JavaScript, לא מעוגןEdit.* תופס גם NotebookEdit. לשם שלם: ^Edit$

ההתאמה רגישה לאותיות גדולות וקטנות: bash לא יתפוס את הכלי Bash. ב-FileChanged וב-StopFailure הכללים צרים יותר: רק | מפריד, ומקף, רווח או פסיק הופכים את הערך לביטוי רגולרי.

סינון לפי ארגומנטים: השדה if

ה-Matcher בודק רק את שם הכלי. השדה if, על המטפל עצמו, משתמש בתחביר של כללי הרשאות ובודק גם את הארגומנטים, כך שהסקריפט לא מופעל בכלל כשאין התאמה. הוא עובד רק באירועי כלים.

.claude/settings.json (קטע)
{
  "matcher": "Bash",
  "hooks": [
    {
      "type": "command",
      "if": "Bash(git *)",
      "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/check-git-policy.sh"
    }
  ]
}

התיעוד מדגיש שהסינון ב-if על פקודות Bash הוא Best-Effort: כש-Claude Code לא מצליח לנתח את הפקודה, הוא מריץ את ה-Hook בכל זאת. לאכיפה קשיחה משתמשים בהרשאות, או בודקים בתוך הסקריפט.

Exec form או Shell form

כשיש args, Claude Code מריץ את command ישירות, בלי Shell, וכל איבר ב-args הוא ארגומנט אחד. זה מה שבחרנו: הנתיב ${CLAUDE_PROJECT_DIR} מוחלף בפנים, ואין בעיות מירכאות גם כשיש רווחים בנתיב. בלי args הפקודה עוברת ל-Shell (sh -c ב-macOS וב-Linux, Git Bash או PowerShell ב-Windows), ואז אפשר צינורות (|) ו-&&.

    •

תקלות נפוצות · לחצו על תקלה

    
ה-Hook לא רץ בכלל

      
בדקו: שהוא מופיע ב-/hooks תחת האירוע הנכון; שה-Matcher תואם את שם הכלי בדיוק, כולל אותיות גדולות; שאתם על האירוע הנכון (PreToolUse לפני, PostToolUse אחרי); שה-JSON בקובץ ההגדרות תקין, בלי פסיק מיותר ובלי הערות.

    

    
בתמליל מופיע hook error

      
הסיבה: הסקריפט יצא עם קוד שאינו 0 או 2, או שהפלט שלו נראה כמו JSON אבל לא תקין.

      
מה לעשות: הריצו אותו ידנית עם JSON לדוגמה. אם מופיע command not found, השתמשו ב-${CLAUDE_PROJECT_DIR} ובנתיב מלא, או ב-Exec form. אם JSON לא תקין, בנו אותו עם json.dumps או jq, לא בשרשור מחרוזות.

    

    
ה-JSON תקין, אבל אין לו השפעה

      
שתי סיבות: שדה ברמה הלא נכונה (למשל permissionDecision מחוץ ל-hookSpecificOutput), או טקסט שפרופיל ה-Shell מדפיס לפני ה-JSON.

      
מה לעשות: פתחו את לוג הדיבוג וחפשו Hook JSON output had unrecognized keys או Hook output does not start with {.

    

    
Hook מסוג Stop לא נותן ל-Claude לסיים

      
הסיבה: הסקריפט חוסם שוב ושוב. Claude Code עוקף Hook כזה אחרי שמונה חסימות רצופות בלי הפעלת כלי ביניהן.

      
מה לעשות: בדקו את השדה stop_hook_active בקלט, וצאו עם 0 כשהוא true.

    

    
ה-Hook איטי וכל תור נתקע

      
מה לעשות: צמצמו את ה-Matcher, הוסיפו if, או העבירו את העבודה לרקע עם "async": true. ברירת המחדל של timeout ל-command היא 10 דקות, וב-UserPromptSubmit היא 30 שניות.

    

    
Hook מסוג PermissionRequest לא מתנהג כמו שציפיתי ב-claude -p

      
לפי התיעוד: במצב לא אינטראקטיבי Hooks כאלה עדיין רצים, חוץ ממצב dontAsk, וקריאה שאף Hook לא החליט עליה ושאין מי שיענה עליה נדחית. קוד יציאה 2 לא נחשב באירוע הזה; דוחים דרך decision ב-JSON.

    

    
ב-Windows הסקריפט לא נמצא

      
מה לעשות: החליפו את python3 ב-py או ב-python. ב-Exec form ב-Windows, command חייב להיות קובץ הרצה אמיתי; קובצי .cmd של npm לא ירוצו בלי Shell.
